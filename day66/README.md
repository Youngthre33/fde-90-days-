# DAY 66: 用json-server 实操 REST API

## 一 学习目标

使用本地json-server 把普通的 db.json文件变成可以接收HTTP 请求的REST API　并亲手验证　GET　POST　PUT　PATCH　和ＤＥＬＥＴＥ

##　本地实验环境

数据文件：day66/db.json

启动命令：
```powershell
npx.cmd json-server@0.17.4 --watch day66/db.json --port 3000 ```

服务器基础地址:
http://127.0.0.1:3000


工单集合地址:
http://127.0.0.1:3000/tickets


## 三、路径中的 `:id`

API 文档中的 `/tickets/:id` 表示访问某一个指定 ID 的工单。

`:id` 是占位符，不是需要原样输入的文字。例如，访问 ID 为 101 的工单，实际地址是 `/tickets/101`。

## 四、已经验证的 API

| 方法 | 路径 | 作用 | 请求正文 | 实际观察结果 |
| ---  | --- | --- | --- | --- |
| GET  | `/tickets` | 获取全部工单 | 无 | `200`，返回工单数组 |
| POST | `/tickets` | 创建一张新工单 | 新工单的数据，不传 ID | `201`，服务器生成 ID 并返回新工单 |
| PUT | `/tickets/:id` | 完整替换指定工单 | 替换后的完整数据 | `200`，没有提供的普通属性可能消失 |
| PATCH | `/tickets/:id` | 修改指定工单的部分属性 | 只传需要修改的属性 | `200`，没有提供的属性继续保留 |
| DELETE | `/tickets/:id` | 删除指定工单 | 无 | 第一次删除返回 `200`，再次删除返回 `404` |

## 五、json-server 的作用

`db.json` 只是一个普通的数据文件，它自己不能接收 HTTP 请求。

`json-server` 是正在运行的服务器程序。它监听 3000 端口，接收浏览器发送的 HTTP 请求，根据请求查找、创建、修改或删除工单，并把变化保存回 `db.json`。

## 六、当前实验的限制

json-server 适合学习和模拟 REST API。目前没有实现用户登录、权限、复杂的数据校验、真实数据库和完整的业务规则。以后这些功能会由 FastAPI 后端代码和数据库负责。
