## 1. 本课要实现什么

上一课定义了tickets表和各列规则。这一课实际新增一张工单：你只提供标题，PostgreSQL按表中规则产生编号、填上默认状态，再把这张工单的内容返回给pgAdmin。

## 3. 先读懂三行SQL

```sql
INSERT INTO tickets (title)
VALUES ('Day109：打印机无法连接网络')
RETURNING id, title, status;
```

第一行：

- INSERT INTO：向表里新增记录。
- tickets：目标表的名字。
- (title)：这次由你明确提供值的列，只有title。括号在这里列出字段，并不是调用Python函数。
- 没有列出id和status：在本课表定义下，由PostgreSQL使用自动编号与默认状态规则补上；不是任意省略的列都一定有合适的默认值。

第二行：

- VALUES：说明新记录各列要使用的实际值。
- 括号里这一项文字，对应上一行的title。
- 单引号标明这是一段文字；引号本身不属于保存的标题。
- 三行连在一起是一条SQL，换行让它更容易读。[官方INSERT说明](https://www.postgresql.org/docs/current/sql-insert.html)

第三行：

- RETURNING：让PostgreSQL把本次实际新增的那条记录的指定内容返回。
- id, title, status：要返回的三个字段，用逗号分开。
- ;：结束整条SQL。

RETURNING特别适合取得数据库刚生成的id。它负责返回值，不负责提交；本课的保存由开启的自动提交完成。[官方RETURNING说明](https://www.postgresql.org/docs/current/dml-returning.html)

## 4. 执行一次并读取真实结果

只选中完整的三行INSERT语句，按F5执行一次。

Data Output应出现这次新增记录的一行：

| 字段 | 本次预期含义 |
| --- | --- |
| id | PostgreSQL本次生成的实际编号，记录看到的数字，不预先认定是1 |
| title | Day109：打印机无法连接网络 |
| status | open，由表的默认值产生 |

这次的id由自动编号功能提供，title来自你写的VALUES，status来自上一课表定义中的DEFAULT 'open'。

本表只要求id唯一，没有规定title唯一。因此重复运行这条INSERT通常会新增另一张同标题工单，不会因为标题相同就自动覆盖。需要查看结果时使用下一步的SELECT，不要把重新运行INSERT当成刷新。

## 5. 换一个查询窗口查回

记下刚返回的id。再次从左侧同一个ticket_app数据库右键打开新的Query Tool，在新窗口只执行：

```sql
SELECT id, title, status FROM tickets;
```

SELECT指定要读取的三列，FROM tickets指定从工单表读取。它可能返回之前的其他记录，找到id与刚才返回值相同的那一行即可，不预设它显示在第一行或最后一行。

新查询窗口也能查到相同id、标题和状态，是本次提交保存的可见证据。RETURNING返回值、提交保存、之后再查询是三个不同动作；本课在自动提交开启的前提下连起来观察。

完整流程：你提供标题 → pgAdmin发出INSERT → PostgreSQL按表规则补编号和状态、检查并新增记录 → RETURNING生成返回结果，自动提交完成保存 → pgAdmin显示结果 → 新查询窗口用SELECT重新读取。

## 8. 本轮补讲：为什么保存之后还要返回

你只提供标题，新增前并不知道PostgreSQL会生成哪个id。假设本次生成27（仅为讲解示例，不是学习者实际结果），RETURNING会把27、标题和open一起交给发出SQL的一方。

当前路径：你在pgAdmin写标题 → pgAdmin发送INSERT → PostgreSQL新增记录并生成编号 → RETURNING将这次新增行的指定字段交回pgAdmin → pgAdmin显示。

以后接回网页时：用户填写标题 → 浏览器发送新增请求 → Python后端向PostgreSQL发送INSERT → 后端取得RETURNING结果 → 后端将编号、标题和状态放入响应 → 浏览器显示新工单，并知道后续编辑或删除应指定哪个id。这是用途说明，不代表当前网页已接通PostgreSQL。

不使用RETURNING也可以保存，之后另发SELECT也能读取；但只按标题找可能得到多条同名记录，RETURNING直接对应本次新增的记录。[PostgreSQL官方说明](https://www.postgresql.org/docs/current/dml-returning.html)

“幂等”关注同一个操作重复后，对目标产生的最终效果是否与执行一次相同。本课普通INSERT每次增加一条，因此不幂等；删除同一个固定id时，第一次后该记录不存在，再次执行后仍不存在，针对这一状态效果是幂等的。第二次是否返回不同提示是另一回事。[HTTP标准中的幂等定义及重复请求响应说明](https://www.rfc-editor.org/rfc/rfc9110.html#section-9.2.2)
