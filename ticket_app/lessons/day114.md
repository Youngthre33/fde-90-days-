## 1. 今天的实际用途

Day113读取了连接信息，今天将它们交给psycopg，让Python真正联系PostgreSQL。psycopg是安装在Python环境里的数据库连接工具；PostgreSQL是管理数据库、处理SQL的服务程序；pgAdmin是另一套供人管理数据库的界面。

本课的路径：你运行Python → Python使用psycopg → 联系配置里的地址和端口 → PostgreSQL接受连接 → 返回可使用的连接对象 → Python显示连接信息 → 关闭这次连接。

这次Python不会通过pgAdmin连接。pgAdmin和Python可以各自连接同一个PostgreSQL服务，它们的连接相互独立。本地练习中这些程序都在同一台电脑上。以后Python和数据库可以部署在不同机器上，按实际位置填写配置。

Day114只建立、观察、关闭；Day115才发送一条固定查询并读取结果；之后逐步学习带编号查询、提交写入和接回网页。

## 2. 已有工具与本课文件

2026-09-28教师核对项目.venv环境：psycopg和psycopg-binary均为3.3.6，不需要重新安装。使用项目解释器，避免调用另一套未安装依赖的Python。

本课文件：`ticket_app/check_db_connection.py`。这是明确用于检查Python能否连接数据库的独立入口，不是另一套工单后端，也不会自动被网页运行。已创建，可打开对照，不需要重复粘贴。密码从现有settings读取，不写进检查代码。

```python
import psycopg

from ticket_app.config import settings


connection = psycopg.connect(
    host=settings.db_host,
    port=settings.db_port,
    dbname=settings.db_name,
    user=settings.db_user,
    password=settings.db_password,
    connect_timeout=5,
)

try:
    print("连接成功，数据库：", connection.info.dbname)
finally:
    connection.close()

print("连接是否已关闭：", connection.closed)
```

## 3. 逐行看建立连接

- `import psycopg`：取得已经安装的连接工具，后面可通过psycopg这个名称使用它。
- `from ticket_app.config import settings`：取得上一课读好的配置。加载config.py时创建配置对象；这一行本身还不向数据库发起连接。
- `connection = psycopg.connect(`：调用psycopg的connect函数。函数使用括号里的信息联系数据库，成功后返回一个连接对象，左边的connection这个变量指向它。settings保存连接信息，connection代表此次已经建立的连接；它们不是同一个东西。
- `host=settings.db_host,`：左边host是connect接受的参数名称，右边取出settings中的地址。这里的等号把参数值交给函数，不是比较相等。
- `port=settings.db_port,`：把数据库端口交给connect，本课配置观察结果是5432。工单后端的8001不承担PostgreSQL连接的角色。
- `dbname=settings.db_name,`：把数据库名称交给connect。左边dbname是这个工具规定的参数名，右边db_name是项目配置里的字段名，二者可以不同。
- `user=settings.db_user,`：把数据库账号交给connect。
- `password=settings.db_password,`：把配置里的密码交给connect，这行没有把密码打印到屏幕。
- `connect_timeout=5,`：设置连接等待超时参数，单位秒；本课联系单一本机地址，防止一直等下去，不展开多个地址的计时规则。
- `)`：结束函数调用。上面多行属于同一次调用，每行末尾逗号用于分隔参数。

连接建立失败会抛出错误，程序不会走到后面的“连接成功”打印。建立连接成功也不能证明工单表存在或具备所有读写权限，那些要到查询和写入课实际核对。

## 4. 逐行看结果与关闭

- `try:`：连接已建立后，执行下面缩进的显示代码；它和后面的finally配合，让这段工作结束时有明确的收尾。
- `print("连接成功，数据库：", connection.info.dbname)`：print把提示文字与数据库名显示到终端。connection是本次连接；info是它的连接信息；dbname是连接使用的数据库名称。这行不是SELECT，没有查询工单。
- `finally:`：无论try里的显示代码正常结束还是发生异常，都会进入这里收尾。这不表示屏蔽错误，也不表示建立连接失败时仍有一个连接可关；connect在try之前，成功后才进入这一段。
- `connection.close()`：调用本次连接对象的close方法，结束Python这一次连接。不会停止PostgreSQL服务、断掉pgAdmin的独立连接或删除已保存数据。这里没有写入，所以没有新增数据需要提交。
- `print("连接是否已关闭：", connection.closed)`：正常走完前面代码后，读取本对象的关闭状态并打印。closed是状态值，没有括号；True表示已经关闭。前面的close()是执行关闭动作，需要括号。这行查看Python对象的状态，不需要重新连接数据库。

连接关闭后，connection这个变量还存在，只是所指的对象已关闭；要再操作数据库，需要重新建立连接。不要把它理解为永久封锁账号或关闭整个数据库服务。

[Psycopg连接、close与closed官方说明](https://www.psycopg.org/psycopg3/docs/api/connections.html)

## 8. 端口与独立连接补讲

本例pgAdmin与Python都可以连接PostgreSQL的同一个127.0.0.1:5432入口。配置中的port表示对方数据库服务的入口，不是给pgAdmin或Python各分配一个不同端口。它们各自建立连接，Python的connection.close()只结束该对象对应的连接，pgAdmin可继续使用自己的连接。把Python数据库目标端口误写成8001，会去找工单HTTP后端，不能借用pgAdmin现有连接。

迁移题原答：“能，因为端口就是一个入口，程序关闭了只是关闭了自己到这个入口的连接，没法关闭其他程序或者pgAdmin到这个程序连接。”判断及核心理由正确：本题connection.close()仅关闭自身连接，同一服务端口可承载不同连接。独立连接理解已复核通过，不再重复同题；当时脚本输出待反馈，随后截图证据见第7节。

## 9. 端口与库名补充说明

学习者追问：为什么不让Python使用5432、pgAdmin使用5431？5432是否固定？5431是否代表数据库别的内容？

讲解：在psycopg.connect中port填写的是目标数据库服务的入口，不是给Python分配自己的服务端口。PostgreSQL默认使用5432，但服务配置可以改成另一个可用端口（变更在服务启动时生效）；客户端必须填写服务实际使用的端口。只把pgAdmin改填5431不会让原服务自动增加5431入口。不同客户端不必各建一个服务入口，连接本身已相互独立。若同机需要运行两套独立PostgreSQL服务，可使用不同端口区分，但本课不实际更改配置或搭建第二套服务。

port用于找到服务入口，dbname指定该服务管理的哪个数据库，SQL中的表名指定查询哪张表；5431不自动代表另一个数据库或表。示例为host=127.0.0.1、port=5432、dbname=ticket_app，然后查询tickets。库名为示例时不表示该库实际已存在。之前8001是Python后端接收网页HTTP请求的入口；本课5432是Python发起数据库连接时访问的目标入口。

官方依据：https://www.postgresql.org/docs/current/runtime-config-connection.html#GUC-PORT 和 https://www.postgresql.org/docs/current/libpq-connect.html#LIBPQ-PARAMKEYWORDS 。无数据库连接、数据写入或端口配置变更。
