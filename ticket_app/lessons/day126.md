# Day126：查询工单处理记录与级联删除

## 本课目标

使用LEFT JOIN查询一张工单及其处理记录，区分有记录、无记录和工单不存在，并验证ON DELETE CASCADE只清理目标工单的记录。

## LEFT JOIN实际结果

工单2存在并有两条处理记录：

- 查询返回2行；
- 两行ticket_id都是2；
- 两行event_id不同；
- 两行note分别对应两次处理。

工单3存在但没有处理记录：

- LEFT JOIN返回1行；
- 工单字段有值；
- event_id和note为NULL。

工单999999不存在：

- LEFT JOIN返回0行。

三种情况：

| 情况 | SQL原始结果 | repository返回 | HTTP结果 |
| --- | --- | --- | --- |
| 工单存在、有记录 | 多行 | 记录字典列表 | 200和记录列表 |
| 工单存在、无记录 | 一行NULL占位 | `[]` | 200和`[]` |
| 工单不存在 | 0行 | `None` | 404 |

## Python整理过程

repository先执行LEFT JOIN并使用fetchall读取全部结果。

```python
if not rows:
    return None
SQL完全没有行时，表示工单不存在。
events = []
for row in rows:
    if row[0] is not None:
        events.append({
            "id": row[0],
            "ticket_id": row[1],
            "note": row[2],
        })
工单存在但没有记录时，LEFT JOIN产生一行NULL占位。row[0] is not None不成立，所以不会建立假记录，最终返回空列表。
main使用：
if events is None:
    raise HTTPException(status_code=404, detail="工单不存在")
[] is None是False，所以工单存在但无记录时正常返回200和空列表。
None is None是True，所以工单不存在时返回404。
不能改成if not events，因为[]和None都会让这个判断成立。
级联删除验证
创建临时工单：
- id：16
- title：Day126：级联删除专用临时工单
- status：open
为工单16建立两条处理记录。
通过Swagger删除工单16，接口返回204。
删除后的实际结果：
- 工单16：0行；
- ticket_id=16的处理记录：0行；
- 工单2：1行；
- ticket_id=2的处理记录：2行。
repository只执行了删除主工单的SQL。属于工单16的处理记录由PostgreSQL根据：
REFERENCES tickets(id) ON DELETE CASCADE
自动删除。
级联方向是父工单到子记录。删除一条处理记录不会反向删除工单，其他工单及其处理记录不会受到影响。
