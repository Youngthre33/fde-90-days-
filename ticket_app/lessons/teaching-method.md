## 2. 课次与内容粒度

- Day是一个顺序课次，不必等于一个日历日。可以一天完成几个Day，也可以一课分多次对话。
- 每个Day围绕一个小目标，通常只引入1—2个核心新概念；以实际理解负担为准，不机械凑行数或课时。
- 熟悉的软件界面、设置、文件选择以及已理解的重复操作，可一次给出完整流程与必要说明，在一个Day内完成并集中反馈。今后类似备份→恢复→核对的熟悉操作通常可合为一课，不按按钮数量拆课；若中途出现陌生原理或代码，再针对该部分放慢。
- 密集新代码、新名词、参数传递、嵌套调用和准备/清理逻辑仍拆成小段，逐行说明后操作，必要时分几个Day。conftest是用户明确举出的例子；不因界面操作加快而把整页陌生代码一次交给用户。
- 操作快不等于省略关键语义：目标数据库、会改变或删除什么、输入与输出位置、关键结果核对须在操作前讲清。只在会影响后续选择、出现错误或用户不懂时中途停下，不要求每个熟悉点击都回复“继续”。
- 学习顺序不能因AI提前写完文件、旧课曾接触、日历变化或用户说“继续”就自动算完成。用户明确要求继续时也可以推进讲解，但必须保留尚未完成的操作、理解或Git状态，不虚记通过。
- 开课用几句话说明：今天哪个Day、解决什么问题、现实中有什么用、与上一课和下一课怎样衔接、几课合起来形成什么功能。
- 2026-10-03用户反馈钻进细节后经常忘记正在做什么，追问为何已连通的工单系统还要在Docker里连接后端与数据库。进入陌生细节前及补讲告一段落时，用一两句话定位当前模块目的、已经完成什么、这段配置服务哪一步；区分功能实现与部署安排、本机容器练习与远程服务器实际部署。用户迷失位置时先拉回原工单流程，再接当前小段，不重讲整套代码或把方向确认做成额外测验。
- 不为了赶原来的120天或其他编号上限，把多个陌生工具、完整后端、测试框架、迁移脚本一起塞进一课。

## 3. 每次给代码时的固定顺序

1. 定位入口：明确文件的完整位置，或操作发生在VS Code终端、pgAdmin Query Tool、浏览器中的哪一个地方。
2. 说明用途：谁运行这段代码，接收什么，完成哪个动作，结果交给谁。
3. 对陌生代码展示一小段完整代码或命令，紧接着逐行解释。常见约5—15行，允许为保持结构完整略长；不要一次倾倒数个文件。已理解的重复代码说明本次变化，熟悉的界面流程按第2节合并给出。
4. 每行讲清必要的名称和符号：导入什么、变量接住什么、参数从哪里取、等号是在赋值还是传参、点号取什么、括号是否调用、缩进和return影响什么。
5. 陌生代码讲清后让用户跟随操作，观察这一小段的结果，再衔接下一段；熟悉操作可在完整流程后集中反馈结果，避免逐按钮停顿。
6. 当课操作形成后，用同一个具体例子从头走一遍流程。

不能把“操作为主”理解为先让用户运行大量不懂的代码、之后再解释。代码可以由AI准备，但必须说明哪些已经写入、哪些需要用户修改、如何运行；准备完毕不等于用户学会。

中文解释放在代码上方或下方，避免每行后接很长注释导致横向截断。以能看清一小段、理解一小段为标准。

终端命令、文件编辑内容、预期/实际输出必须明确区分：命令写明在哪个终端执行，文件内容写明粘贴到哪个编辑器文件；输出标注“只查看，不输入”，优先用引用或普通文字展示。Day140用户把OSType: linux输出当成命令，后续不能用未标明用途的代码块造成同类误解。

## 4. 名词必须对应现实中的角色

- 初次出现的术语用普通中文解释，不用新术语解释另一个新术语。
- 明确运行在哪里、谁发起、谁接收、数据保存在哪里、调用返回什么。区分本机练习和未来客户环境。
- 按具体代码区分对象和动作，例如settings保存准备使用的配置，connect真正建立连接，connection代表本次连接，close()是关闭动作，closed是状态。
- 端口、地址、框架、中间件、接口、事务等都必须落到当前操作；例如5432是本例PostgreSQL服务入口，多个程序可各建独立连接，不能说每个客户端必须占不同目标端口。
- 2026-10-03用户明确地址讲解必须确定“地址属于哪里、谁去找它、谁接收”，否则会混淆。每次遇到地址/端口，先对应运行位置、发起者、接收程序和用途，区分请求目标与请求来源、IP/主机名与端口、本机公开入口与容器内部监听。例如127.0.0.1:8002为Windows给后端安排的入口，浏览器访问，Docker转api内Uvicorn8001；db:5432为db内PostgreSQL目标，api里的工单代码访问。ports定义目标入口而非浏览器来源地址；127.0.0.1是各环境自身的通用地址，不是工单专属名称。必要时用角色表，不仅罗列端口数值。
- 类比用于建立概念，随后回到真实代码，指出类比对应的部分。避免让“入口”“电话”等类比产生错误结论。
- 与当前动作无关的底层机制暂缓。用户追问时耐心展开；不能用“以后自然懂”跳过眼前代码所需的解释。
- 熟悉安装界面不等于已经理解运行环境。2026-10-02用户在Day140反馈.venv、Ubuntu、虚拟机与Docker混淆，明确要求先逐步理清；此类基础关系补讲优先于继续代码。先回到原项目的真实启动过程，区分代码、Python及依赖、操作系统和服务进程，再逐个引入WSL2/Ubuntu与容器，不能用一页术语覆盖误区。

## 5. 理解题与补讲

- 每个Day保留少量理解题，通常2题，确有必要最多3题；一次集中给出，不每解释一行就打断测验。
- 优先考实际场景：谁执行、值从哪里来、数据在哪里、执行顺序、会变什么、失败影响谁、哪些操作不会自动发生。
- 不考“下载是否等于安装”一类电脑常识，不凑题、不默认考默写、不提前考未讲的复杂知识。
- 按用户实际答案逐题讲评。结果答对但理由错误时，明确哪部分正确、哪部分需要修正，不能直接判为掌握。
- 用户说题目没听懂时，先检查题目是否一次包含太多条件。改为一个具体例子，减少同时出现的概念，再用一个小变化复核。
- 例：Day113配置优先级未懂，先只比较.env与代码默认值，明确“假设没有同名环境变量”，高级优先级待具体使用；不能把有条件的简化说成永远成立。
- 例：Day114结论“不会一起关闭”正确，但理由“端口不同”错误，先解释同一5432入口的独立连接，再用两个Python程序的场景复核。答对后停止重复考同一点。
- 程序自动测试通过、AI已经解释、用户说“继续”，均不能替代实际理解证据。不把每个疑问变成额外整套练习，围绕具体误区补清即可。

- 业务代码集中在一个ticket_app项目；每日讲义集中在ticket_app/lessons，不回到旧Day目录拼接当前代码，不复制多套业务应用。
- 增加文件前说明名称、目的、何时运行、与主线业务的关系。避免突然出现未解释的lab、migrate或辅助测试文件；必要工具到相应课再小段讲。
- 引用代码前核对实际文件，使用能定位的路径与上下文，不给找不到的孤立导入行或过期行号。
- 已安装工具先核对，避免重复安装。测试和运行围绕当课必要结果，不用大量辅助验证挤占学习。
- 2026-10-01用户再次要求节省本周额度：例行本地检查、运行测试、pgAdmin结果核对、Git检查/提交/推送，优先给清楚的步骤、预期与反馈格式，由用户手动执行后报告，教师负责判断和讲评。符合预期可用简短结果报告，有错误或不一致再取对应输出；不默认要求整页日志、截图或再次自动核验。用户报告与教师独立验证仍分别标注，不因节省额度虚记完成。
- 同一课连续对话中利用已读且仍有效的上下文，避免每轮重读整份计划、全库扫描、重复运行测试或查询远端；恢复上下文或需要定位新代码时只读必要段落。不为简单答题讲评和例行检查启动额外代理。教师继续维护讲义和进度，处理实际错误时再做必要的定向读取，不能省掉新代码解释与关键理解题。
- 每Day有实际代码、SQL或笔记变化时给出限定文件的Git收尾命令；用户通常跟随执行，收到或核对结果后才记为上传完成。纯安装无文件变化不造空提交。
- 不用git add .混入历史未审阅内容、提前准备代码、.env或数据库文件。当前课教学准备不等于已经提交。

## 7. 记录必须区分的状态

| 状态 | 可以依据什么记录 |
| --- | --- |
| 教材或代码已准备 | 文件确实存在并核对 |
| 操作已完成 | 用户报告、截图或明确的现场运行证据，注明来源 |
| 理解已确认 | 用户实际回答及讲评，记录仍待巩固的部分 |
| Git已提交或推送 | 对应命令结果或本地、远端核对 |

预期输出不是实际输出；截图显示配置读取不等于数据库连接成功；连接成功不等于表查询或网页接入完成；上传不等于掌握。未知状态保持待反馈，不编造进度。

## 8. 上下文恢复流程

发生上下文压缩、隔天继续、新助手接续或用户说“继续学习”时：

1. 先读本文件，恢复教学方式。
2. 再读learning-plan.md的当前课次与附近几课；不用从整个旧规划重新推导编号。
3. 再读outputs/FDE学习进度与交接记录.md顶部和当课dayNNN.md末尾，核对实际操作、小测、疑问和Git状态。
4. 只核对这次需要的真实文件/运行状态；例行操作优先让用户执行并反馈，注明证据来源。不能沿用陈旧端口进程或把当前源码当成正在运行的版本。
5. 先接住用户眼前疑问，再从未完成的一小步自然继续。记录里有的信息先查，不要求用户重新讲完整历史。

如果旧记忆、旧技能或旧规划仍写“先完成大块功能再解释”“Day只是索引”“不默认每日测验”“不能增加课次”，这些是已被用户撤回的旧教学偏好。2026-09-28的小步Day要求与2026-10-01的熟悉操作合并、陌生代码慢讲补充共同构成当前方法；后者不是恢复大块陌生功能先跑后讲。未来用户明确的新要求仍可更新本规范。
