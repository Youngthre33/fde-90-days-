## 2. 先看现有记录

从pgAdmin左侧的ticket_app数据库打开Query Tool。每次选中当前完整的一条SELECT执行，避免把上一课保留的INSERT也一起选中执行。

```sql
SELECT id, title, status
FROM tickets;
```

- SELECT id, title, status：本次要读取编号、标题和状态三列；逗号分隔列名。
- FROM tickets：从名为tickets的表读取；分号结束这条SQL。
- 观察真实记录，记下其中一个id。这里没有ORDER BY，不预设结果按编号排列。
- 如果没有记录，先核对查询窗口连接的数据库和Day109保存的目标，不把空结果假定为数据被删除。

## 3. 按编号找一张

下面的27只是示例。执行前改成你刚查到的真实编号：

```sql
SELECT id, title, status
FROM tickets
WHERE id = 27;
```

- 第一行：仍然读取编号、标题和状态三列。
- 第二行：仍然从tickets表读取；语句还没结束，分号放到最后。
- 第三行：WHERE给出筛选条件；id是每条记录的编号；=在这个条件里表示比较是否相等，不是把所有编号改成27；27是要查找的编号，数值不用单引号。
- 有这个编号时，按本课主键规则最多返回一行；没有时返回0行，不会因此自动新增记录，也不等于SQL语法出错。

## 4. 按状态找一组

```sql
SELECT id, title, status
FROM tickets
WHERE status = 'open';
```

- 前两行与上例相同。
- WHERE status = 'open'：只让状态为open的记录出现在本次结果里。
- status是列名，open是我们保存的状态文字，表示待处理；单引号表示文字值，不是列名。
- 这里的等号也是比较，不会把其他记录的状态改成open。
- 如果已有记录全是open，筛选结果与刚才查询全部记录相同也正常；不符合条件的记录仍保留在数据库中。

WHERE控制哪些记录进入查询结果。[PostgreSQL官方WHERE说明](https://www.postgresql.org/docs/current/queries-table-expressions.html#QUERIES-WHERE)

## 5. 在筛选后加上排序和条数限制

以下两项以前学过，本课放回实际查询里复习：

```sql
SELECT id, title, status
FROM tickets
WHERE status = 'open'
ORDER BY id DESC
LIMIT 2;
```

逐行读：

1. SELECT id, title, status：结果里要有编号、标题、状态三列。
2. FROM tickets：读取工单表。
3. WHERE status = 'open'：结果只保留待处理记录。
4. ORDER BY id DESC：按编号从大到小排列本次结果。ORDER BY指定按什么排序，id是排序依据，DESC表示从大到小；这是结果排序，不是改变数据库中每条记录的编号。[官方排序说明](https://www.postgresql.org/docs/current/queries-order.html)
5. LIMIT 2：从排序后的结果里最多取两条。只有一条符合条件就返回一条，没有就返回0条；2表示条数，不表示工单编号，也不会删掉其余记录。[官方LIMIT说明](https://www.postgresql.org/docs/current/queries-limit.html)

整句需求：取出状态为open的工单，按编号从大到小排，返回前面最多两条的编号、标题和状态。

这里只能称为“编号最大的最多两条待处理工单”，不是严格按创建时间查最新两条。本课没有创建时间列，不扩展该话题。

## 6. 从发出命令到显示结果

你在pgAdmin写查询条件 → pgAdmin把SQL发给PostgreSQL → PostgreSQL读取tickets并按查询要求筛选、排序、限制结果条数 → 返回结果数据 → pgAdmin的Data Output显示。

上面是帮助理解查询要求的逻辑顺序，不是保证数据库内部必须逐行扫描再依次执行的物理过程。

## 7. 两道理解题

以下是假设数据，供读题，不需要实际插入：

| id | status |

| 3 | open |
| 7 | open |
| 10 | done |

1. 对这张假设表执行第5节的完整查询，返回的两个编号是什么，先后顺序是什么？
