```python
import httpx

from ticket_app.config import settings


def generate_ticket_advice(ticket_text: str) -> str:
    if not settings.ai_api_key:
        raise ValueError("请先配置 TICKET_AI_API_KEY")

    messages = [
        {"role": "system", "content": "你是工单助手。用中文给出工单摘要和建议下一步，不要声称已执行操作。"},
        {"role": "user", "content": ticket_text},
    ]

    response = httpx.post(
        "https://api.deepseek.com/chat/completions",
        headers={"Authorization": f"Bearer {settings.ai_api_key}"},
        json={
            "model": "deepseek-flash",
            "messages": messages,
            "thinking": {"type": "disabled"},
            "stream": False,
            "max_tokens": 800,
        },
        timeout=60.0,
    )
    response.raise_for_status()
    data = response.json()
    return data["choices"][0]["message"]["content"]
```

## 讲解要点与返回路径

截图的 base_url 是模型服务根地址，加 /chat/completions 才是本次请求接口。OpenAI 兼容描述请求/响应格式，不代表必须向 OpenAI 付费。复用 requirements.txt 已声明的 httpx，不先引入另一套 SDK。

Python 导入 ticket_ai → 导入 config 建立 settings 并读取 .env → 调用 generate_ticket_advice，文字传到 ticket_text → messages / JSON 请求体 → HTTPX 序列化并发送 HTTPS POST 和 Bearer 请求头 → DeepSeek 验证其 API Key、调用选定模型 → JSON 回到 response → raise_for_status 检查成功状态 → json 解析成 Python 字典 → choices 列表第 0 项的 message.content → return 回到原调用处 → print 显示在终端。

HTTPX 的 timeout=60.0 是各网络阶段超时设置，不保证整个调用精确在60秒内结束；不是让模型回答60秒。max_tokens 为输出上限，不是800汉字。API响应外层JSON与content内中文字符串需区分。非2xx响应时raise_for_status中断后面的解析/return，终端收到异常；不虚构当前已有网页错误提示。

```javascript
async function handleAdviceAction(id, adviceButton) {
    if (generatingAdvice) {
        return;
    }

    generatingAdvice = true;
    adviceButton.disabled = true;
    adviceOutput.textContent = `正在为工单 #${id} 生成建议...`;

    try {
        const response = await fetch(`${TICKETS_API_URL}/${id}/advice`, {
            method: "POST",
            headers: getAuthHeaders()
        });

        if (!response.ok) {
            throw new Error(`生成建议失败，HTTP状态码：${response.status}`);
        }

        const data = await response.json();
        adviceOutput.textContent = `工单 #${data.ticket_id}\n\n${data.advice}`;
    } catch (error) {
        adviceOutput.textContent = error.message;
    } finally {
        generatingAdvice = false;
        adviceButton.disabled = false;
    }
}
```

这里generatingAdvice仅防止当前页面在一次生成未结束时重复发起模型请求，不讲复杂并发系统；textContent按文字显示，模型返回的Markdown星号可能原样出现，第一版不引入渲染库。f-string与JS模板字符串区分，dataset DOM字符串经已有Number转换为数字ID。浏览器使用工单token；只有后端读取模型密钥。POST接口只需路径ID，不传body，也不写Content-Type；服务器自行查库。main.py返回{ticket_id,advice}不是DeepSeek原始choices，前端只读data.advice。
