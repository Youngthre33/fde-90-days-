## 2. 只读懂tickets这一段

代码与项目schema.sql中的tickets定义一致；本课不执行整份文件里的ticket_events部分。

```sql
CREATE TABLE IF NOT EXISTS tickets (
    id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    title TEXT NOT NULL CHECK (length(trim(title)) > 0),
    status TEXT NOT NULL DEFAULT 'open'
        CHECK (status IN ('open', 'in_progress', 'done'))
);
```

### 第一行：建哪张表

CREATE TABLE表示创建表。tickets是表名。IF NOT EXISTS表示已有同名对象时跳过创建并提示；不会删掉旧记录，也不会检查或自动升级旧表来匹配本段定义。左括号开始列出各列的定义。[官方CREATE TABLE说明](https://www.postgresql.org/docs/current/sql-createtable.html)

### 第二行：id

- id：工单编号这列的名称。
- INTEGER：保存整数。
- GENERATED BY DEFAULT AS IDENTITY：新增时不提供编号，PostgreSQL会自动生成；BY DEFAULT也允许明确提供编号，但仍要符合其他规则。
- PRIMARY KEY：主键，用来唯一标识一张工单，不允许编号重复或为NULL。自动生成编号与保证不重复是不同规则。
- 末尾逗号：下一列定义还会继续。

[官方自动编号说明](https://www.postgresql.org/docs/current/ddl-identity-columns.html)

### 第三行：title

- title：工单标题这一列。
- TEXT：保存文字。
- NOT NULL：不允许用NULL表示标题值缺失；它本身不禁止空字符串。
- CHECK (...)：保存数据时必须满足括号中的条件。
- trim(title)：检查时去掉标题两端的普通空格。
- length(...)：计算去掉这些空格后的字符数。
- > 0：字符数必须大于0，因此空字符串或全是普通空格的标题不能通过。

例如标题是三个普通空格，trim的检查结果为空字符串，length结果为0，条件不成立。这里trim用于检查，不会自动把保存的title替换成去掉空格后的文字。

### 第四、五行：status

两行合起来定义同一列，中间换行只是方便阅读。

- status：状态这列。
- TEXT NOT NULL：保存文字，禁止NULL。
- DEFAULT 'open'：新增时没有提供状态，默认使用open；明确提供NULL不会自动变成open。
- CHECK (status IN (...))：检查提供的状态必须属于括号内的选项。
- 'open'、'in_progress'、'done'：分别表示待处理、处理中、已完成；单引号标明它们是文字值。

这些规则由PostgreSQL执行。pgAdmin只是把建表指令发过去。[官方约束说明](https://www.postgresql.org/docs/current/ddl-constraints.html)、[官方默认值说明](https://www.postgresql.org/docs/current/ddl-default.html)

### 最后一行

)结束这张表的定义，;结束整条SQL。定义各列的逗号用于分隔，最后一列后不再加逗号。

## 3. 执行并查看表

在当前Query Tool的执行按钮旁下拉选项中，确认Auto commit（自动提交）开启，意思是执行成功后自动提交保存这次操作；本课不新增事务写法。[官方执行工具栏](https://www.pgadmin.org/docs/pgadmin4/latest/query_tool_toolbar.html)

选中上述完整CREATE TABLE语句，按F5或点击Execute script执行。新建时Messages会报告创建结果；如果已有tickets，会有已存在、跳过的提示。这个提示不证明旧表规则与新定义完全相同。

然后选中下面这条，单独执行：

```sql
SELECT id, title, status FROM tickets;
```

SELECT后面的三个名称是要读取的列；逗号分隔列名；FROM tickets表示从tickets表读取。此查询只用于观察已有结果，不新增工单。

- 刚创建的表没有工单：Data Output显示三个列名，数据行数为0。
- 表里以前已有工单：显示原有记录，保留即可；不要求为了和示例一致删除旧记录。

该查询成功能确认表可访问且三列可查询，不能证明所有约束都已安装。若本次跳过建表，后续写入前应按已有表属性核对默认值和约束；如果遇到列不存在或定义不同，先处理差异，不删表重建。

## 4. 本课两道理解题与讲评（2026-09-28）

1. 新创建了tickets表，还没有新增任何工单。此时id/title/status三列是否已经存在？会不会因为status有DEFAULT 'open'，就自动多出一张工单？
   - 学习者回答：“已经存在，不会多出，只是默认的，只有提交了其他数据没有提交status才会默认open。”
   - 讲评：判断正确，能区分表结构与数据行。用语明确为“新增一条记录时没有提供status，PostgreSQL为该列填入open”；设置默认值本身不会创建记录。
2. 按本课定义，新增一张标题正常的工单，没提供id和status，它们各由谁产生、按什么规则产生？如果明确把status写成NULL，会不会被自动改成open？
   - 学习者回答：“id会自动默认序列1，status默认是open；不会，应该会报错，明确说了不能NULL。”
   - 讲评：默认状态及NULL被拒绝均正确；编号补充为取下一个自动编号。全新且未使用过的默认编号通常从1开始，但不是每张工单都填1，也不是重复建表就从1重来。不把简略表达直接认定为已证明的概念错误；下一课实际新增时观察返回编号，不另补题。
