## 2. 先认识配置文件里的五项值

`.env.example`是示例模板。程序实际要读的文件叫`.env`，在同一个ticket_app目录里；修改示例模板不会自动改变程序的实际配置。今天先看字段，不覆盖已有.env。

下面五行对应此前在pgAdmin里填过的连接信息：

```dotenv
TICKET_DB_HOST=127.0.0.1
TICKET_DB_PORT=5432
TICKET_DB_NAME=ticket_app
TICKET_DB_USER=postgres
TICKET_DB_PASSWORD=<只在本机填写的数据库账号密码>
```

1. 第一行：`TICKET_DB_HOST`是配置项名称，等号右边是地址。本次练习的`127.0.0.1`表示运行Python的这台电脑。
2. 第二行：`TICKET_DB_PORT`保存数据库程序接收连接的端口，本项目默认5432。另一个已有字段`TICKET_PORT`默认8001，是工单后端的入口，两者用途不同。
3. 第三行：`TICKET_DB_NAME`保存要使用的数据库名称。本次学习库是`ticket_app`；写入这个名称本身不会创建数据库。
4. 第四行：`TICKET_DB_USER`保存登录PostgreSQL的数据库账号名。`postgres`在这里是账号，不是上一行的数据库名称。
5. 第五行：`TICKET_DB_PASSWORD`保存该数据库账号的密码。这里的尖括号文字是讲义占位符，不是实际密码；更改配置里的密码也不会替你重设数据库账号密码。

这些行是“配置名称=配置值”，不是SQL，不在pgAdmin的Query Tool里执行。它们先交给Python的配置读取工具，下一课才用于建立连接。

项目.gitignore中已有`.env`这一项，用于让Git默认忽略尚未跟踪的本地配置文件。它不是加密功能，也不能自动清除已经进入Git历史的内容；本课笔记只保留占位文字。

## 3. config.py怎样规定字段和读取位置

先在config.py顶部找到这三行。文件里还有其他已有内容，今天不用全部展开：

```python
from pathlib import Path
from pydantic import Field
from pydantic_settings import BaseSettings, SettingsConfigDict
```

- 第一行：从Python的pathlib工具中取得Path，用它描述文件路径。
- 第二行：取得Field，用它给配置项设置默认值和允许范围。
- 第三行：取得两个配置工具。BaseSettings提供读取、整理和检查配置的能力；SettingsConfigDict用来告诉它按什么规则读取。逗号分开这次取得的两个名称。

再看紧接着的这段：

```python
class Settings(BaseSettings):
    model_config = SettingsConfigDict(
        env_prefix="TICKET_",
        env_file=Path(__file__).resolve().parent / ".env",
        env_file_encoding="utf-8",
    )
```

1. 第一行：定义名为Settings的配置规则，并使用BaseSettings提供的能力。冒号后缩进的内容属于这一组规则。今天先按这个实际用途理解，不展开类和继承的内部机制。
2. 第二行：调用SettingsConfigDict，把括号里的读取规则整理后交给model_config。等号是把右边结果赋给左边名称。
3. 第三行：`env_prefix`规定配置名称前面加`TICKET_`。例如后面的`db_name`字段对应示例中的`TICKET_DB_NAME`；当前设置允许这里的大写配置名与小写字段名对应。
4. 第四行：规定读取哪个文件。`__file__`指当前config.py；`Path(...)`把它作为路径处理；`.resolve()`得到绝对路径；`.parent`取它所在的目录；`/ ".env"`在这个路径后接上文件名。这里的`/`用于拼路径，因此无论终端从哪个目录启动，目标都是config.py旁边的.env。
5. 第五行：用utf-8方式读取文件里的文字。
6. 第六行：右括号结束本次设置；上面的逗号分隔各项规则。

随后找到数据库字段这一段。保留原文件的其他字段；本讲义只截取今天相关的五行：

```python
    db_host: str = "127.0.0.1"
    db_port: int = Field(default=5432, ge=1, le=65535)
    db_name: str = "ticket_app"
    db_user: str = "postgres"
    db_password: str = "<源码中的密码默认值已隐藏>"
```

1. 第一行：字段名是db_host，冒号后的str表示文字；引号中的地址是没有其他来源提供该字段时使用的默认值。
2. 第二行：db_port使用整数int。Field中的default=5432给出默认端口，ge=1要求不小于1，le=65535要求不大于65535。来自配置文件的端口文字会被转换和检查。
3. 第三行：db_name保存数据库名称，代码默认ticket_app。
4. 第四行：db_user保存数据库账号名，代码默认postgres。
5. 第五行：db_password保存密码文字。当前源码也有默认字符串，这里已经隐藏；不能把“存在默认值”理解为“数据库一定接受这个密码”。不要将讲义里的占位文字抄回源码。

这些字段目前只是规定值的名称、类型、默认值或范围，没有执行SQL。

## 4. Settings怎样变成settings

文件最后一行是：

```python
settings = Settings()
```

这一行由Python执行：右边`Settings()`按刚才的规则读取配置、检查值并创建一个配置对象；左边的小写settings接住这个对象。大写Settings是规则名称，小写settings是本次读好的配置结果。

当前这一行的空括号表示没有在这里直接提供字段值。同一个字段若在多处都有值，优先使用：

1. Python进程已有的同名环境变量，也就是启动这个程序时它已经带着的配置值。
2. config.py旁边.env文件中的值。
3. Settings代码里写的默认值。

这是逐个字段决定取值的优先级，不是“有.env就整份忽略代码默认值”。某项没写时，其他项仍可用各自来源；选中的值如果类型或范围错误，会报告配置错误，不会因为错误就自动换用较低优先级值。[Pydantic配置优先级说明](https://pydantic.dev/docs/validation/latest/concepts/pydantic_settings/#field-value-priority)

例如，没有同名进程环境变量，.env里写了`TICKET_DB_NAME=ticket_practice`，即使代码默认ticket_app，创建出的settings.db_name也会是ticket_practice。这只是解释优先级的假设，不要求你真的改库名。

`settings.db_name`中，点号表示“取出settings里的db_name这一项”。以后连接代码会从这个对象取得连接参数。仅创建settings不会检查数据库是否存在、密码是否正确，也不会打开数据库连接。

settings创建后，修改.env不会自动改写这个现有对象；需要重新创建配置对象才能重新读取。本课的观察命令每次启动一个新的Python进程，所以再次运行会重新读取。

## 5. 只观察四个非密码字段

这一步由你在已有项目Python环境的PowerShell终端执行，不在pgAdmin里输入。教师本轮不会代读实际.env。

```powershell
Set-Location 'C:\Users\Administrator\Documents\GitHub\fde-90-days-'
.\.venv\Scripts\python.exe -c "from ticket_app.config import settings; print(settings.db_host, settings.db_port, settings.db_name, settings.db_user)"
```

- 第一行：把终端当前目录切到项目仓库根目录，以便找到ticket_app。
- 第二行的`.\.venv\Scripts\python.exe`：使用当前项目.venv目录内的Python解释器，沿用项目已经安装的依赖。开头的`.\`表示从当前仓库目录开始找；后面的`-c`让Python执行引号中的一小段代码。
- `from ticket_app.config import settings`：读取config.py中的settings；在这次新进程首次加载该文件时，末尾的Settings()会执行。
- 中间的分号：把导入和打印这两个Python动作隔开。
- `print(...)`：把括号内四个字段按顺序显示在终端；逗号分开要打印的值。只打印地址、端口、库名、账号，没有打印密码。

如果这四项都沿用本课配置，输出形如：

```text
127.0.0.1 5432 ticket_app postgres
```

这只是预期示例，以你的实际输出为准；不同的值先沿优先级检查，不直接覆盖配置。输出能证明这次Python读到了哪些参数，不能证明已经连接数据库。若报错，先报告出错字段名称和错误类型，不发送密码或完整配置对象；今天不因此跳入数据库连接或重装步骤。

本课流程是：Python加载config.py → 按规则取得各项配置 → 创建settings → 打印指定的非密码字段。pgAdmin和数据库都没有接收本课的SQL命令。
