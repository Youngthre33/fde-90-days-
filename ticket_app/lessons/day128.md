# Day128：第一项最小pytest数据库测试

## 本课目标

在独立的ticket_app_test数据库中创建一张测试工单，再根据返回编号重新查询，并使用assert比较创建结果和查询结果。

## 最小测试

文件：

`ticket_app/tests/test_day128_minimal.py`

代码：

```python
from ticket_app import ticket_repository


def test_create_and_find_ticket():
    created = ticket_repository.create_new_ticket(
        "Day128：pytest新增并查询"
    )

    found = ticket_repository.find_ticket_by_id(
        created["id"]
    )

    assert found == created
pytest根据test_开头的函数名识别测试。
created接收新增函数返回的工单字典。
found根据数据库生成的id重新查询，不是直接复制created。
assert found == created要求重新查询结果与创建结果相等。
测试数据库选择
保留.env中的日常配置：
TICKET_DB_NAME=ticket_app
只在测试PowerShell终端临时设置：
$env:TICKET_DB_NAME = "ticket_app_test"
配置检查确认Python读取到ticket_app_test。
本课使用：
python -m pytest --noconftest ticket_app/tests/test_day128_minimal.py -v
暂时不加载已有的复杂conftest，Day129再学习fixture。
实际结果
正确断言运行时：
- pytest发现1项测试；
- 最终显示1 passed；
- ticket_app_test中查询到测试工单；
- 日常ticket_app中同标题查询为0行。
随后故意把断言改为：
assert found["status"] == "done"
数据库实际状态为open，所以pytest显示FAILED。
失败发生在INSERT提交以后。assert只负责比较，不负责数据库回滚。失败以后，已经提交的测试工单仍然保存在测试数据库中。
观察完成后，代码恢复为：
assert found == created
测试数据已从ticket_app_test清理，临时环境变量已移除，配置重新显示ticket_app。
关键理解
- 一项测试通过只证明它实际覆盖的创建和查询流程。
- 它不能证明修改、删除、API、网页和所有数据库功能都正常。
- assert负责比较实际结果与预期结果。
- assert失败不会自动撤销已经提交的数据库事务。
- rollback只能撤销当前尚未提交的事务。
- 测试需要独立环境和清理机制，避免失败残留影响下一项测试。
