# Day125：建立工单处理记录表

## 本课目标

在PostgreSQL中建立ticket_events表，让一张工单可以拥有多条处理记录，并使用外键阻止错误归属。

## 实际操作

开始查询ticket_events时，PostgreSQL返回relation does not exist，证明表尚未建立。

在ticket_app数据库的public Schema中执行：

```sql
CREATE TABLE IF NOT EXISTS ticket_events (
    id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    ticket_id INTEGER NOT NULL
        REFERENCES tickets(id) ON DELETE CASCADE,
    note TEXT NOT NULL CHECK (length(trim(note)) > 0)
);
创建成功后，在pgAdmin的：
ticket_app → Schemas → public → Tables
中看到了tickets和ticket_events。
给真实存在的工单2新增两条处理记录：
INSERT INTO ticket_events (ticket_id, note)
VALUES
    (2, 'Day125：已联系用户确认问题'),
    (2, 'Day125：已安排技术人员处理')
RETURNING id, ticket_id, note;
两条记录自己的id不同，但ticket_id都是2，说明它们是工单2的两次不同处理记录。
随后尝试使用不存在的ticket_id=999999新增处理记录。PostgreSQL根据：
REFERENCES tickets(id)
拒绝了这次INSERT。
实际检查结果：
- ticket_id=999999：0行；
- ticket_id=2：仍然是2行；
- 错误INSERT没有影响已经成功保存的合法记录。
关键理解
- ticket_events.id表示处理记录自己的编号。
- ticket_events.ticket_id表示这条记录属于哪张工单。
- 一张工单可以对应多条处理记录。
- 每条处理记录只能指向真实存在的tickets.id。
- ON DELETE CASCADE表示删除主工单时，属于它的处理记录跟随删除。
- 删除一条处理记录不会反过来删除主工单。
