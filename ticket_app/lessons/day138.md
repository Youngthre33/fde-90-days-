## 第一部分：检查、进入或安装Linux环境

WSL是Windows提供的运行Linux环境的方式；Ubuntu是可在其中安装的Linux发行版。本课优先复用已安装的Ubuntu（含版本名称）或Debian，不依据旧记录声称机器已安装。官方简化安装要求Windows10版本2004/构建19041及以上或Windows11；有错误时按实际输出处理，不猜测系统版本或固件设置。

在Windows PowerShell执行：

```powershell
wsl --list --verbose
```

wsl调用Windows的WSL管理工具，--list列出已安装发行版，--verbose同时显示运行状态与WSL1/2版本。VERSION不是Ubuntu发行版版本号。若只见docker-desktop等Docker内部环境，不把它当作本课日常Linux开发环境。

- 已有Ubuntu/Ubuntu-24.04/Debian等常规Linux：按实际NAME进入，不重复安装。示例：列表实际名为Ubuntu时，执行wsl -d Ubuntu；实际为Ubuntu-24.04时，执行wsl -d Ubuntu-24.04。已有其他类型先反馈名称再适配。
- 没有常规Linux发行版：开始菜单打开以管理员身份运行的PowerShell，执行下面安装命令。若提示重启，先保存工作再由用户重启；不自动操作重启。

```powershell
wsl --install -d Ubuntu
```

--install请求安装，-d Ubuntu指定发行版。第一次进入会要求创建Linux用户名与密码，用户名可选小写fde。Linux账号独立于Windows用户和PostgreSQL账号；输入密码时通常没有字符或星号回显，正常输入后回车。密码保留本机，不要求贴出。安装/下载/启动报错时只取对应输出，不盲目重装。

安装并完成初始账号设置后，从Windows PowerShell进入：

```powershell
wsl -d Ubuntu
```

命令中Ubuntu必须与列表中实际NAME一致。Linux提示符类似username@电脑名:路径$，与PowerShell的PS C:\...不同；示例不是实际机器输出。

## 后半段已备课：启动文件服务、看日志、查进程、停止

2026-10-02已核对网页源码：main.py当前CORS允许http://127.0.0.1:5500，web/constants.js的API为http://127.0.0.1:8001/tickets。此次使用5501和直接访问constants.js，避免常用5500服务混淆，也不要求完整工单页面或数据库此时运行。只启动本机文件服务，不改变业务代码、CORS、API地址或数据库。本段命令已准备，用户尚未执行反馈。

### 两个核心概念

进程是程序正在运行的一次实例，启动Python文件服务后产生一个进程；PID是这次进程的编号。日志是程序记下的运行事件，本课观察收到哪个文件请求和返回什么状态码。文件存在与进程运行是不同证据。

### A窗口：启动

在Ubuntu进入原项目目录后执行：

```bash
cd /mnt/c/Users/Administrator/Documents/GitHub/fde-90-days-
```

再单独执行：

```bash
python3 -m http.server 5501 --bind 127.0.0.1 --directory ticket_app/web
```

python3是Linux Python；-m运行指定模块；http.server是Python自带的文件HTTP服务；5501是本次服务端口；--bind 127.0.0.1绑定本机回环地址；--directory ticket_app/web将该目录作为返回文件的起点。使用自带模块，无须新增业务脚本/依赖。Serving HTTP on ...只是启动提示，不等于已处理浏览器请求；该程序在当前终端前台持续运行，等待请求期间不回到shell提示符。错误如Address already in use取真实输出适配，不盲目停止其他进程。

### 浏览器：取已有文件并对应日志

Windows浏览器打开http://127.0.0.1:5501/constants.js，预期显示已有JS文件文字。这里直接取文件，未运行完整工单网页的JavaScript，不请求8001工单接口、不执行SQL。WSL正常本机转发允许Windows浏览器访问Linux服务；若打不开取错误和Ubuntu启动输出，再定位，不预改防火墙或开放外网。

返回A窗口预期日志类似GET /constants.js HTTP/1.1和200；客户端地址/时间以实际为准。200表示这一文件请求成功，不证明后端/数据库运行；再次访问可能304，对应缓存核对。浏览器额外请求favicon.ico且返回404不等于constants.js失败，按具体请求路径识别。

### B窗口：查正在运行的进程

另外打开一个Windows PowerShell窗口，执行wsl -d Ubuntu，进入第二个Linux终端（不在A正在运行服务的终端输入检查命令）。执行：

```bash
pgrep -af 'http.server 5501'
```

pgrep按条件查进程；-f匹配完整启动命令；-a显示PID和完整命令；引号使包含空格的匹配文字成为一个参数。预期类似1234 python3 -m http.server 5501 --bind 127.0.0.1 --directory ticket_app/web，1234仅例子，不当作真实PID；若有多行据用户输出判断，不自行杀进程。pgrep工具不可用时取报错再适配。

### 停止与集中核对

回到A窗口按Ctrl+C，当前前台文件服务退出并出现shell提示符；文件仍在原目录。B窗口再次执行同一pgrep，预期这次服务不再出现。浏览器文件页面按Ctrl+F5强制重新请求，预期无法连接此服务；已显示的文字或缓存不是服务仍运行的证据。此流程说明的是当前前台进程，不能扩展成关闭任意终端就一定停止所有后台服务。
