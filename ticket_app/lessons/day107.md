### 随堂补充：数据库实际保存在哪里

学习者询问：现在数据是否在本机，以后是否单独设备保存，然后pgAdmin和PostgreSQL都连接设备管理？

本课连接的是本机PostgreSQL。2026-09-28教师只读核对服务启动参数及运行中的postmaster.pid，数据目录为`C:/Program Files/PostgreSQL/18/data`。这是PostgreSQL管理的数据目录；ticket_app库的数据由底层文件组织，不能把项目同名文件夹当作它的保存位置。[官方文件布局](https://www.postgresql.org/docs/current/storage-file-layout.html)

常见远程部署是：开发者电脑的pgAdmin → 网络 → 数据库服务器上的PostgreSQL → 该服务器可用的磁盘存储。PostgreSQL运行在服务端并管理数据文件，pgAdmin从另一台电脑发送管理请求；两者不是都作为同级客户端直接连接一块纯存储设备。服务器可为实体机或云端虚拟机，数据库与应用也可部署在同一台服务器，不要求一定另买专用设备。[官方客户端与服务端说明](https://www.postgresql.org/docs/current/tutorial-arch.html)

客户使用业务网页时，Python后端直接连接PostgreSQL，不经过pgAdmin；pgAdmin关闭不等于PostgreSQL停止，也不会删除已提交数据。此补充不新增测验，Day107原操作和两题仍待反馈。

## 1. 找到本项目的数据库

教师已核对现有项目配置与示例：数据库名称沿用ticket_app，不另起一套名字。这里的ticket_app是PostgreSQL里的数据库名称；同名项目文件夹存放代码，数据库负责保存业务数据，两者各有用途。

在pgAdmin里展开已连接项目下的Databases：

- 已有ticket_app：直接使用它，保留已有内容。
- 没有ticket_app：右键Databases → Create → Database。在General页面的Database填写ticket_app；Owner保持当前登录账号，本课程默认是postgres；其余保持默认，点击Save。pgAdmin会把创建要求发给PostgreSQL，由PostgreSQL实际创建数据库。

Create是创建，Database是数据库，Owner是这个数据库的所有者账号。若界面报错，按具体报错处理，不通过删除旧库重试。[官方建库窗口说明](https://www.pgadmin.org/docs/pgadmin4/latest/database_dialog.html)

本课不用额外学习CREATE DATABASE语法，不修改Python配置。

## 2. 从目标数据库打开Query Tool

右键Databases下面的ticket_app，选择Query Tool。

Query Tool可以理解为“写数据库指令、运行并查看结果的窗口”。从ticket_app打开的新查询窗口以这个数据库为目标。

| 窗口区域 | 本课用途 |
| --- | --- |
| 上方SQL Editor | 输入要执行的SQL |
| 下方Data Output | 查看返回的结果 |
| 下方Messages | 查看执行提示或报错 |

布局可能因版本和个人设置不同略有差异，按标签名称找区域。[官方查询窗口说明](https://www.pgadmin.org/docs/pgadmin4/latest/query_tool.html)

## 3. 逐项读懂这一条SQL

在这个新窗口上方输入：

```sql
SELECT current_database();
```

- SELECT：让PostgreSQL返回后面指定的结果。
- current_database：PostgreSQL自带的函数，作用是取得当前连接所使用的数据库名称；它在PostgreSQL里执行。
- ()：调用这个函数。这里不用额外传入参数，PostgreSQL根据当前连接知道要返回哪个名称。
- ;：标记这条SQL语句的结束。输入分号本身不会替你按执行按钮。

这句话的意思是：“请告诉我，这个查询窗口当前连接的数据库叫什么名字。”这里取得的是函数返回的名称，所以无需FROM指定一张工单表。[PostgreSQL官方函数说明](https://www.postgresql.org/docs/current/functions-info.html)

## 4. 执行并读结果

选中这一整条SQL，点击工具栏的Execute script，或在SQL编辑区域按F5执行。[官方执行按钮与快捷键](https://www.pgadmin.org/docs/pgadmin4/latest/query_tool_toolbar.html)

在下方Data Output应看到类似结果：

| current_database |
| --- |
| ticket_app |

current_database是返回结果这一列的名称；下面的ticket_app才是查询得到的数据库名称。这是查询结果的展示，不是刚建了一张工单表。若界面在列名下面额外显示name，那是类型提示，本课先读取实际返回值。

如果返回postgres，说明这次查询仍在postgres数据库的连接上执行。回到左侧ticket_app，右键打开它的Query Tool，在新窗口重新执行本句。成功提示、左侧高亮或以前的结果都不能代替这次实际返回的库名。

## 5. 查询窗口与左侧列表的关系

已经打开的查询窗口有自己的连接。只在左侧单击另一个数据库，并不会自动把原查询窗口切过去。

本课切换目标的方法是：从目标数据库右键打开一个新的Query Tool，再执行current_database()核对。pgAdmin还有专门切换连接的功能，后续需要时再学；这里不是说查询窗口永远无法换库。

本次流程：你在查询窗口写SQL → 点击执行 → pgAdmin通过该窗口的连接发送SQL → PostgreSQL取得当前数据库名并返回 → pgAdmin在Data Output显示名称。

本句不会新增、修改或删除工单。它只能证明当前窗口连接到了返回名称所指的数据库，不证明工单表已建立，也不证明Python后端已经接通。

## 6. 本课两道小测与讲评（2026-09-28）

1. 已经从ticket_app打开Query Tool，后来只在左侧单击postgres，仍在原查询窗口执行SQL。这条SQL会发给哪个数据库？你用什么操作核实？
   - 学习者回答：“还是发给原窗口的数据库，可以看返回的内容。”
   - 讲评：正确。应在原查询窗口重新执行SELECT current_database();，读取这次返回的数据库名称来核实；不是只看左侧高亮或旧结果。
2. 执行SELECT current_database();后，Data Output出现一行ticket_app。这是不是新建了一张表或新增了一条工单？这一行究竟是什么？
   - 学习者回答：“不是，只是显示当前的数据。”
   - 讲评：没有新建表或新增工单的判断正确；“当前的数据”不够精确，本句返回的是当前连接的数据库名称ticket_app，不是该库中的工单内容。已就此补充，不追加重复题。
