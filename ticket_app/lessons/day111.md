## 1. 今天实现什么

把一张已有工单从open（待处理）改为in_progress（处理中）。这对应以后用户在网页点击“开始处理”的数据库动作。

今天仍由你在pgAdmin发出SQL，PostgreSQL修改ticket_app数据库里的tickets表，再把结果交回pgAdmin。网页和Python后端不参与本次操作。下一课Day112才练习删除指定工单。

本课两项主要内容：UPDATE说明修改哪张表，SET说明哪一列改成什么。WHERE和RETURNING沿用前两课内容。

## 2. 先选出真实工单，再查修改前的内容

从pgAdmin的ticket_app数据库打开Query Tool，保持Auto commit（自动提交）开启。本课由自动提交保存成功的修改，不另开显式事务。[pgAdmin官方工具栏说明](https://www.pgadmin.org/docs/pgadmin4/latest/query_tool_toolbar.html)

先执行这一条，找一张待处理工单：

```sql
SELECT id, title, status
FROM tickets
WHERE status = 'open'
ORDER BY id;
```

- 第一行：读取编号、标题和状态三列。
- 第二行：从tickets表读取。
- 第三行：只找状态为open的记录。
- 第四行：按编号从小到大排列；没有写DESC时，默认升序。分号结束这条SQL。

从结果里选一个真实id，记下标题和原状态。如果结果为空，核对窗口的目标数据库和现有记录，不虚构一条工单或直接修改不认识的编号。

下面统一以27作为讲解示例。执行时把前查、修改、复查三处的27全部换成刚选中的同一个真实编号。

先单独执行：

```sql
SELECT id, title, status
FROM tickets
WHERE id = 27;
```

第一行决定读取三列，第二行决定从工单表读取，第三行只查这个编号。确认这一行就是准备修改的工单，当前status为open。

## 3. 逐行解释修改命令

```sql
UPDATE tickets
SET status = 'in_progress'
WHERE id = 27
RETURNING id, title, status;
```

### 第一行：UPDATE tickets

UPDATE表示修改已有记录，tickets是要修改的表名。和上一课SELECT读取数据不同，这次会实际改变记录。

### 第二行：SET status = 'in_progress'

- SET说明需要写入的新值。
- status是要修改的列。
- 等号在这一行表示把右边的值设到左边的列中。
- 'in_progress'是新状态文字，表示处理中，单引号标明文字值。

因此这一行是“把状态设为处理中”。本课只在SET中指定status，id和title保持原值。[PostgreSQL官方UPDATE说明](https://www.postgresql.org/docs/current/sql-update.html)

### 第三行：WHERE id = 27

WHERE限定要修改哪些记录。这里的等号是在判断编号是否等于27，不是把编号改为27。id是主键，所以本课这个条件最多选中一张工单；没有匹配编号时修改0行，不会自动新增。

SET回答“改成什么”，WHERE回答“改哪条”。读取SQL中的书写顺序，不要理解为先改整张表再筛选；只有符合WHERE的记录才会按SET修改。

### 第四行：RETURNING id, title, status;

将本次实际修改后的记录的编号、标题、状态返回给发出SQL的pgAdmin。RETURNING负责提供结果，本课保存由已开启的自动提交完成；分号结束整条SQL。[官方RETURNING说明](https://www.postgresql.org/docs/current/dml-returning.html)

本条语句的人话：找到编号为27的那张工单，把状态改成处理中，再把修改后的编号、标题和状态交回来。

## 4. 执行并再次读取

确认替换成真实编号后，选中完整四行UPDATE执行一次。Data Output应出现同一id、原来的标题和in_progress状态。

然后只选中下面这条SELECT再次执行，编号仍使用同一个真实值：

```sql
SELECT id, title, status
FROM tickets
WHERE id = 27;
```

第一行指定读取内容，第二行指定表，第三行指定同一编号。预期仍读到in_progress。

这里RETURNING是修改命令带回的结果，最后的SELECT是另发一次读取请求；在本课自动提交开启的前提下，可核对刚才修改保存后的值。

逻辑流程：你选中已有工单的编号 → pgAdmin发送带编号条件的UPDATE → PostgreSQL找到匹配记录并设置新状态 → 返回修改后的内容，自动提交完成保存 → pgAdmin显示 → 你再发SELECT读取同一条记录。

以后接回网页时，浏览器发送编号和目标状态，Python后端接收、检查后让数据库完成修改，再把结果交回浏览器显示。今天直接操作数据库，不代表当前网页已经接通PostgreSQL。

## 5. 两道理解题

假设下面是操作前的数据，仅用于读题，不要求新增这些行：

| id | title | status |
| --- | --- | --- |
| 3 | 登录失败 | open |
| 7 | 打印机无法连接网络 | open |

1. 对这张假设表执行UPDATE tickets SET status = 'in_progress' WHERE id = 7;之后，3和7的状态分别是什么？7的标题会不会改变？
2. 如果只去掉上面语句里的WHERE id = 7，仍然保留SET status = 'in_progress'，会修改哪些记录、哪一列？编号和标题会不会一起变化？这题只预测结果，不执行这条没有编号条件的修改。
