```python
def estimate_ticket_advice_cost(usage: dict) -> dict:
    cache_hit_tokens = usage["prompt_cache_hit_tokens"]
    cache_miss_tokens = usage["prompt_cache_miss_tokens"]
    output_tokens = usage["completion_tokens"]

    cache_hit_cost = cache_hit_tokens * 0.04 / 1_000_000
    cache_miss_cost = cache_miss_tokens * 2 / 1_000_000
    output_cost = output_tokens * 8 / 1_000_000

    peak_cost = cache_hit_cost + cache_miss_cost + output_cost
    off_peak_cost = peak_cost / 2

    return {
        "peak_yuan": peak_cost,
        "off_peak_yuan": off_peak_cost,
    }
```

代码用途：把实际用量按三类分别乘单价，再将相加结果交回调用处。1_000_000等于1000000，下划线只方便读数。此处浮点数用于教学估算，不执行扣费，也不代替平台账单。

沿同一份数据逐句追踪：

1. 调用estimate_ticket_advice_cost(usage)时，参数usage接收调用处那份字典；def本身不执行计算，:dict与->dict是类型提示。
2. 三次方括号读取分别把800、200、300交给cache_hit_tokens、cache_miss_tokens、output_tokens。字段来自平台约定，左边变量名由我们起。不能把prompt_tokens=1000再额外加到两种输入上，否则重复计费。
3. cache_hit_cost=800×0.04÷1000000=0.000032元；cache_miss_cost=200×2÷1000000=0.000400元；output_cost=300×8÷1000000=0.002400元。每个右侧算完交给对应左侧变量，再执行下一行。
4. peak_cost接住三项之和0.002832元；off_peak_cost接住一半0.001416元。此处是本次查询单价下的两种时段估算，不是已经确定实际时段或真实扣款。
5. return把两项装进一个字典交回调用者。例如cost=estimate_ticket_advice_cost(usage)，由cost接收；cost["peak_yuan"]读高峰估算，cost["off_peak_yuan"]读空闲估算。return后本次函数结束。

熟悉单位：0.002832元小于1分钱；同样用量按高峰价重复1000次为2.832元。重复次数仅用于估算，不表示后续调用一定同样用量、缓存命中或相同时段。

本合并版取代第二段“循环中立即算cost”的过渡写法：循环只保存平台统计，退出读取时在finally统一计算和记录一次。这样正常返回、读取报错或生成器被关闭时，都有机会记录已经取得的统计；费用记录并不意味着后续TicketAdvice检查通过。无usage记未知，有usage但建议失败仍按该份统计估算。最终未到、进程未执行收尾等情形不承诺已经取得统计。

计时范围：messages准备好之后、HTTP请求开始之前，到读取与响应关闭后执行finally。perf_counter来自Python标准库time，适合测经过时间；差值单位秒，不是年月日时钟。yield把片段交给上层时的等待也包含在差值中，因此它是这段后端调用流程的经过时间，不能标成纯模型推理耗时或网页最终渲染时间。参考[Python perf_counter文档](https://docs.python.org/3.12/library/time.html#time.perf_counter)。

日志由ticket_app/run.py现有logging.basicConfig配置输出；logger=logging.getLogger(__name__)在本模块取得同一日志体系中的记录者。正常日志为info，统计无效为warning。业务从其他入口启动时须确认该入口配置日志；本课沿用现有python -m ticket_app.run入口。

```python
# 阅读路线：main.py 传入工单文字 → A2～A8 逐段交出文字 → A10 检查完整建议。

import json
import logging
from time import perf_counter

import httpx
from pydantic import BaseModel, Field

from ticket_app.config import settings

logger = logging.getLogger(__name__)


# A1：先写好完整建议的格式要求；真正执行检查的位置在下面 A10。
class TicketAdvice(BaseModel):

    # 最多 3 项不等于必须有 3 项，空列表也符合这里的数量要求。
    summary: str = Field(min_length=1)

def estimate_ticket_advice_cost(usage: dict) -> dict:

    cache_miss_tokens = usage["prompt_cache_miss_tokens"]
    output_tokens = usage["completion_tokens"]

    # 统计必须是非负整数；缺字段由读取时报错，不能补0冒充用量。
    for token_count in (cache_hit_tokens, cache_miss_tokens, output_tokens):
        if type(token_count) is not int or token_count < 0:
            raise ValueError("AI用量数据无效")

    cache_miss_cost = cache_miss_tokens * 2 / 1_000_000
    output_cost = output_tokens * 8 / 1_000_000

    off_peak_cost = peak_cost / 2
    return {"peak_yuan": peak_cost, "off_peak_yuan": off_peak_cost}

def log_ticket_advice_usage(usage, elapsed_seconds):

                    # 发完了不一定是完整答案；如因长度上限结束，原因就不是 stop。
                    if finish_reason != "stop":
                        raise ValueError("AI建议未完整生成，请重试")
                    # 确认正常结束，结束这个函数；上层的 for 因而读完，随后检查完整建议。
                    return

                # A7：把这一条平台消息的 JSON 文字读成 Python 字典，交给 data。
                # 这是外层消息；其中 delta.content 仍可能只是建议 JSON 的一小段文字。
                data = json.loads(payload)
                if "error" in data:
                    raise ValueError("AI生成失败，请重试")

                # 当前消息有统计才保存；没有时不抹掉此前收到的统计。
                reported_usage = data.get("usage")
                if reported_usage is not None:
                    usage = reported_usage

                # choices 是平台规定的字段。缺少时先取 []；没有候选项就等下一行。
                choices = data.get("choices", [])
                if not choices:
                    continue

                # 取第一项；这里的 [0] 是列表里的第一个位置。
                choice = choices[0]
                if choice.get("finish_reason") is not None:
                    # 有明确结束原因才更新；中间消息中的 None 不覆盖之前保存的值。
                    finish_reason = choice["finish_reason"]

                # delta 中的 content 是这次新增的文字；没有该字段时 get 得到 None。
                # 它不保证是完整建议，也不同于 main.py 循环中累计拼接后的 content。
                part = choice["delta"].get("content")
                if part:
                    # 把这一小段交给上层 for 的 part 接住，然后暂停在这里。
                    # 上层要求下一段时，从这里继续；yield 不会直接把文字画到网页上。
                    yield part

        # A8：若没有通过 A6 的正常 return 就读到了连接末尾，不能假装生成成功。
        raise ValueError("AI生成连接提前结束，请重试")
    finally:
        # 正常return、读取报错或生成器关闭，离开try时都在这里收尾。
        elapsed_seconds = perf_counter() - started_at
        log_ticket_advice_usage(usage, elapsed_seconds)


# A10：完整建议检查。main.py 在收齐所有片段后，把完整字符串传到这里。
# : str / -> dict 只是输入、返回类型提示；真正的转换和检查是下面三行。
def parse_ticket_advice(content: str) -> dict:
    # 建议 JSON 字符串 → 字典。例如 '{"summary":"打印机", ...}' → {...}。
    # 这里只读出文字里原本写好的结构，不会把错误的字段自动排成正确格式。
    data = json.loads(content)
    # 按 A1 检查字段和类型；通过后得到 TicketAdvice 对象，失败就报错交给上层。
    advice = TicketAdvice.model_validate(data)
    # 检查后的对象 → 普通字典，return 把字典交回 main.py 的 advice 接住。
    return advice.model_dump()
```

### 新增代码的具体执行顺序

1. started_at=perf_counter()：假设起点读数是100.00，交给started_at；它只是解释用读数，不是真实请求记录。usage=None表示本次尚未取得统计。
2. 进入try，仍由httpx.stream请求并逐行接收。普通消息reported_usage=None，if跳过，usage保留原值；最后一条统计消息reported_usage为完整字典，再赋给usage。新增reported_usage表示当前一条消息带来的值，usage保留本次调用已取得的统计。
3. 正常收到[DONE]会检查stop并执行return，但return完成之前先进入finally。若读取报错，也先finally，再把原错误继续交给main.py。若流式生成器被关闭，finally也执行；不把进程被强制终止当作可以保证执行。
4. 假设第二次perf_counter读103.25，elapsed_seconds=103.25-100.00=3.25。3.25秒交给elapsed_seconds，下一行把usage及3.25作为两个参数交给log_ticket_advice_usage。
5. 若usage=None，logger.info记录耗时与未知费用，return结束统计函数，原生成流程继续自己的成功/失败收尾；未知不等于0元。若usage是字典，进入try计算cost并记录三类实际数量和两种费用估算。
6. {:.2f}是f字符串里的显示规则，保留两位小数；{:.8f}保留八位小数，避免小金额只显示0.00。它们不改变保存的原始数值，也不发起扣款。
7. KeyError表示缺字段，TypeError表示数据类型不合适，ValueError表示本估算函数拒绝了无效数量。统计函数就地记录“用量数据无效”，不让这些统计错误改写原建议的生成结果。完整合并版仅给估算函数增加了三项非负整数检查；不接受缺值补0。
