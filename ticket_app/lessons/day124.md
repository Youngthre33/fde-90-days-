# Day124：网页删除指定工单

## 本课目标

从网页发送DELETE请求，让后端真正删除PostgreSQL中的指定工单，并区分204与重复删除的404。

## 实际操作

删除目标：

- id：1
- title：day123:网页修改标题成功
- status：in_progress

实际结果：

1. 删除前，pgAdmin可以查询到id=1。
2. 网页点击一次“删除”后，该行从页面消失。
3. pgAdmin再次查询id=1，结果为0行。
4. Ctrl+F5刷新网页以后，该工单没有重新出现。
5. 在Swagger中重复删除id=1，返回404和“工单不存在”。
6. 其他工单仍然保留。

## 完整流程

浏览器发送DELETE请求：

`DELETE /tickets/1`

执行顺序：

`main.py → ticket_service.py → ticket_repository.py → PostgreSQL`

repository执行：

```sql
DELETE FROM tickets
WHERE id = %s
RETURNING id, title, status

WHERE限定只删除目标编号。
RETURNING把被删除行原来的数据交回Python代码，不表示数据库中仍然保存着这行。
第一次删除时，fetchone()取得被删除行，main判断返回值不是None，最后根据接口的status_code=204返回空响应正文。
第二次删除时，数据库已经没有目标行，fetchone()得到None，main中的if deleted_ticket is None成立，raise HTTPException返回404和“工单不存在”。
理解题结果
1. RETURNING取得旧数据与数据库已经删除并不矛盾。旧数据只是暂时返回给Python，用来判断是否真正删除到一行。
2. 第一次删除匹配到数据，main执行空return并按接口配置返回204；第二次匹配不到数据，main判断None后抛出404。
