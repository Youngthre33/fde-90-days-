## 1. 今天解决什么问题

客户已经创建了一张工单，但标题可能需要补充，处理人员也需要把状态从“待处理”改为“处理中”。Day123让网页的修改动作真正保存到PostgreSQL，并在刷新或重新查询后仍然存在。

今天只增加两个核心概念：

1. 浏览器使用`PATCH`表示只修改一张工单的一部分字段，例如只发title，或者只发status。
2. repository使用`UPDATE ... SET ... WHERE ...`修改PostgreSQL中指定编号的记录。

本机练习中的流程：

```text
用户点编辑/保存或状态按钮
    ↓
浏览器main.js向8001发送PATCH /tickets/15
    ↓
main.py验证请求并调用service
    ↓
service调用repository
    ↓
repository经5432执行UPDATE并提交
    ↓
更新后的完整工单返回浏览器
    ↓
浏览器替换数组中的id=15并重新显示
```

5500仍只提供网页文件；pgAdmin仍只用于本课核对，不参与客户网页修改。

## 2. 为什么点击“编辑”还没有修改数据库

浏览器把工单列表中的按钮点击统一交给`handleTicketListClick(event)`。点“编辑”时执行：

```javascript
if (action === TICKET_ACTION.EDIT) {
    editingId = id;

    render(
        tickets,
        editingId
    );

    return;
}
```

- `action`来自被点击按钮的`data-action`，编辑按钮登记的值是`edit`。
- `TICKET_ACTION.EDIT`也是`"edit"`，两边相等时进入这个if。
- `editingId = id`把当前工单编号记成正在编辑的编号。
- `render(tickets, editingId)`仍使用浏览器当前数组重新显示页面。
- render发现某张工单的id等于editingId，就把那张的标题文字换成输入框，并把“编辑”按钮变成“保存”。
- `return`结束这一次点击处理，防止继续判断下面其他按钮动作。

这一段没有`fetch`、没有访问8001、没有SQL。因此点击“编辑”只改变网页显示方式，还没有修改PostgreSQL。

## 3. 点击“保存”才进入修改函数

编辑状态下，原按钮的动作变成`save`。再次点击时执行：

```javascript
if (action === TICKET_ACTION.SAVE) {
    await handleSaveAction(
        id,
        clickedButton
    );

    return;
}
```

- `action`等于`save`时进入这个if。
- `handleSaveAction`是负责保存标题的异步函数。
- 第一个参数`id`是要修改的工单编号；本课目标是15。
- 第二个参数`clickedButton`是当前“保存”按钮，函数会在请求期间暂时禁用它。
- `await`等待整个保存流程完成，再继续当前点击处理函数。
- `return`结束本次点击分发。

## 7. 浏览器怎样发送标题PATCH

取得`newTitle`以后，保存函数执行：

```javascript
const response =
    await fetch(
        `${TICKETS_API_URL}/${id}`,
        {
            method: "PATCH",
            headers: {
                "Content-Type":
                    "application/json"
            },
            body:
                JSON.stringify({
                    title: newTitle
                })
        }
    );
```

- `response`准备接收完整HTTP响应。
- `fetch`是浏览器真正发送网络请求的动作，`await`等待后端处理完成。
- 当`TICKETS_API_URL`是`http://127.0.0.1:8001/tickets`、id是15时，模板字符串组成`http://127.0.0.1:8001/tickets/15`。
- `method: "PATCH"`表示只修改已有工单的一部分内容。
- 请求头说明正文是JSON。
- `JSON.stringify({title: newTitle})`把只含新标题的JavaScript对象转换成JSON文字。

本次计划输入`day123:网页修改标题成功`，实际请求正文将是：

```json
{"title":"day123:网页修改标题成功"}
```

它没有status字段，因此这次只要求后端改title，状态应继续保持open。

## 9. saveButton参数为什么要传入

列表点击函数先执行：

```javascript
const clickedButton = event.target;
```

`event.target`是用户真正点击的那个页面元素；点击“保存”时，`clickedButton`就指向当前保存按钮。调用函数时：

```javascript
await handleSaveAction(
    id,
    clickedButton
);
```

第一个实参把工单编号交给形参`id`；第二个实参把同一个按钮对象交给形参`saveButton`。名字可以不同，传递关系相当于：

```text
clickedButton → saveButton
```

函数需要按钮对象，正是为了开始时执行`saveButton.disabled = true`防止重复点击，并在`finally`中执行`saveButton.disabled = false`允许失败后重试。`id`负责定位数据，`saveButton`负责控制界面元素。也可以在函数里重新查询按钮，但调用者已经拥有准确对象，直接传入更清楚，避免再次查找。

成功时`render`会重新创建这一行，旧保存按钮会离开页面，新生成的是普通“编辑”按钮；`finally`对旧按钮解除禁用不会伤害新页面。失败时没有重新render，原保存按钮仍在页面，`finally`解除禁用尤其重要，否则用户不能修正后重试。

## 12. main.py怎样接住部分修改

```python
@app.patch(
    "/tickets/{ticket_id}",
    response_model=Ticket,
)
def update_ticket(
    ticket_to_update: TicketUpdate,
    ticket_id: int = Path(ge=1),
):
    update_data = ticket_to_update.model_dump(
        exclude_unset=True,
        exclude_none=True,
    )

    updated_ticket = update_ticket_by_id(
        ticket_id,
        update_data,
    )

    if updated_ticket is None:
        raise HTTPException(status_code=404, detail="工单不存在")

    return updated_ticket
```

- 路径中的`{ticket_id}`接收地址末尾编号；本次为1。
- `TicketUpdate`验证可选的title/status；title若提供必须非空，status若提供只能是三种合法值。
- `model_dump(exclude_unset=True, exclude_none=True)`只留下请求真正提供且不为None的字段。本次得到`{"title": "day123:网页修改标题成功"}`，没有status。
- main把编号与修改字典交给service；返回None时转404，成功时返回完整工单。

## 13. service与repository怎样执行UPDATE

service只转交：

```python
def update_ticket_by_id(ticket_id: int, update_data: dict):
    return ticket_repository.update_ticket_by_id(ticket_id, update_data)
```

repository：

```python
def update_ticket_by_id(ticket_id: int, update_data: dict):
    with get_connection() as connection:
        if "title" in update_data:
            connection.execute(
                "UPDATE tickets SET title = %s WHERE id = %s",
                (update_data["title"], ticket_id),
            )

        if "status" in update_data:
            connection.execute(
                "UPDATE tickets SET status = %s WHERE id = %s",
                (update_data["status"], ticket_id),
            )

        cursor = connection.execute(
            "SELECT id, title, status FROM tickets WHERE id = %s",
            (ticket_id,),
        )
        row = cursor.fetchone()

    return row_to_ticket(row)
```

- 本次update_data只有title，因此第一个if执行，第二个if跳过。
- `SET title = %s`指定修改title列；第一个参数是新标题。
- `WHERE id = %s`限定只改编号1；第二个参数是ticket_id。没有WHERE会改全表。
- UPDATE后再SELECT同一编号，fetchone取回完整的新行。
- `with`正常退出时提交UPDATE并关闭连接；SELECT/fetchone只取结果，不负责提交。
- `row_to_ticket`把行整理成字典并逐层返回浏览器。
