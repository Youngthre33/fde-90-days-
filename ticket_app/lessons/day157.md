**D：完整复制函数，位于renderTicketAdvice之后、handleAdviceAction之前。**

```javascript
async function handleCopyAdvice() {
    if (copyingAdvice || !finalAdviceText) {
        return;
    }

    const textToCopy = finalAdviceText;
    const generationAtCopy = adviceGeneration;
    copyingAdvice = true;
    copyAdviceButton.disabled = true;
    copyAdviceMessage.textContent = "正在复制...";

    try {
        await navigator.clipboard.writeText(textToCopy);
        if (generationAtCopy === adviceGeneration) {
            copyAdviceMessage.textContent = "已复制完整建议，可以粘贴到其他地方。";
        }
    } catch {
        if (generationAtCopy === adviceGeneration) {
            copyAdviceMessage.textContent = "复制失败，请重试，或选中建议文字手动复制。";
        }
    } finally {
        copyingAdvice = false;
        copyAdviceButton.disabled = !finalAdviceText;
    }
}
```

沿打印机建议看过程：先确认没有别的复制等待、已经保存了最终文字；textToCopy记住本次点击的全文，generationAtCopy记住本轮编号。随后锁住复制按钮，浏览器执行writeText把文字放进系统剪贴板；await成功回来后才提示已复制。失败时catch只更新复制提示，finalAdviceText和建议正文保留，因此可以重试。finally解除复制等待标志，再根据当前是否仍有最终文字决定按钮能否恢复。

如果等待复制时用户开始另一轮生成，adviceGeneration已增加，旧复制回来时两编号不相等，就不把旧成功/失败提示写到新建议旁边。开始新生成不强行把copyingAdvice改成false，因为旧操作实际还没结束。

新增浏览器功能为navigator.clipboard.writeText：交入字符串，等待写入成功；无可用接口或被拒绝时由catch提示。已按[MDN文档](https://developer.mozilla.org/en-US/docs/Web/API/Clipboard/writeText)核对API行为，实际环境需允许剪贴板写入。

```javascript
// D：把当前收到的建议显示到页面
function renderTicketAdvice(id, advice, finished) {
    let summary = "";
    let nextSteps = "";
    let missingInfo = "";
    let stateText = "生成中";

    if (typeof advice.summary === "string") {
        summary = advice.summary;
    }
    if (Array.isArray(advice.next_steps)) {
        nextSteps = advice.next_steps
            .filter(item => typeof item === "string")
            .join("\n");
    }
    if (Array.isArray(advice.missing_info)) {
        missingInfo = advice.missing_info
            .filter(item => typeof item === "string")
            .join("\n");
    }
    if (finished) {
        stateText = "生成完成";
    }

    adviceOutput.textContent =
        `工单 #${id}（${stateText}）\n\n` +
        `【工单摘要】\n${summary}\n\n` +
        `【建议下一步】\n${nextSteps}\n\n` +
        `【待补充信息】\n${missingInfo}`;
}

// E：请求新接口，逐段读取消息
async function handleAdviceAction(id, adviceButton) {
    if (generatingAdvice) {
        return;
    }
    generatingAdvice = true;
    adviceButton.disabled = true;
    adviceOutput.textContent = `正在为工单 #${id} 生成建议...`;
    let reader = null;

    try {
        // E1：发送请求，取得读取正文的工具
        const response = await fetch(`${TICKETS_API_URL}/${id}/advice/stream`, {
            method: "POST",
            headers: getAuthHeaders()
        });
        if (!response.ok) {
            throw new Error(`生成建议失败，HTTP状态码：${response.status}`);
        }
        if (!response.body) {
            throw new Error("没有收到可读取的响应内容");
        }
        reader = response.body.getReader();
        const decoder = new TextDecoder("utf-8");
        let buffer = "";

        // E2：收到新内容就接起来，取出完整的行
        while (true) {
            const result = await reader.read();
            if (result.done) {
                throw new Error("AI建议未完整生成，请重试");
            }
            buffer += decoder.decode(result.value, { stream: true });
            const lines = buffer.split("\n");
            buffer = lines.pop();

            // E3：逐行识别预览、完成或失败
            for (const line of lines) {
                if (!line.trim()) {
                    continue;
                }
                const message = JSON.parse(line);
                if (!message || typeof message !== "object") {
                    throw new Error("收到无法识别的AI消息");
                }
                if (message.type === "error") {
                    throw new Error(
                        typeof message.message === "string"
                            ? message.message
                            : "AI建议生成失败，请重试"
                    );
                }
                if (message.type !== "preview" && message.type !== "done") {
                    throw new Error("收到无法识别的AI消息");
                }
                const advice = message.data;
                if (!advice || typeof advice !== "object" || Array.isArray(advice)) {
                    throw new Error("AI建议数据格式不正确，请重试");
                }

                const finished = message.type === "done";
                renderTicketAdvice(id, advice, finished);
                if (finished) {
                    return;
                }
            }
        }
    } catch (error) {
        // E4：显示失败提示
        adviceOutput.textContent = error.message;
    } finally {
        // E5：恢复按钮，结束本次读取
        generatingAdvice = false;
        adviceButton.disabled = false;
        if (reader) {
            try {
                await reader.cancel();
            } catch {
                // 清理时的错误不覆盖已经显示的结果
            }
            reader.releaseLock();
```

## 局部补讲：media_type声明交给谁、格式名称怎么读（2026-10-15）

用户自述整段代码已理解，仅问media_type="application/x-ndjson"为何用于规定格式，以及右边两部分各自含义。不要重复讲完整C，也不要把这次理解反馈扩展为前端已经接通；聚焦这一行并纠正此前“规定”可能造成的误解：这里是声明实际正文采用的格式，不会自动改造正文。

media_type为StreamingResponse已有参数名，表示媒体/内容类型；传入的字符串用于设置HTTP响应头Content-Type: application/x-ndjson。用“响应头是随数据一起发送的说明信息，正文是具体消息”配两条打印机preview样例说明，响应头不会成为建议文字显示出来。右侧整体是约定格式名称，application为应用程序处理数据的大类，斜杠分隔大类/具体类型，x-ndjson为子类型。NDJSON展开为Newline Delimited JSON：Newline换行，Delimited分隔，JSON沿用已学格式；x-为历史上非标准/私有扩展的命名前缀，不代表流或实时，也不是项目临时发明的值。

为什么写：让HTTP响应明确告知接收程序正文按多条JSON、换行分隔组织，不靠猜测或仅靠项目口头约定。对比application/json的一个JSON文档与本响应每行各自完整的多条消息；NDJSON不是“把一个JSON缩进排成多行”。正文JSON与换行由B的dumps、text+\n准备，StreamingResponse负责逐次供给正文，media_type负责说明格式。即使省略，按已约定格式手写的前端仍可能读取成功，不把它讲成流式开关；设置后也不会自动让浏览器把建议渲染到页面。

## 第 1 小段：yield 怎样交出一段，再继续

操作位置：VS Code 现有 PowerShell 终端，项目根目录 C:\Users\Administrator\Documents\GitHub\fde-90-days-。沿用现有 .venv，无需新增环境或业务文件。

先阅读 Python 部分：

```python
def advice_parts():
    yield '先检查电源。'
    yield '再检查连接线。'
    yield '记录具体报错。'

for part in advice_parts():
    print('收到：', part)
```

- def advice_parts(): 定义函数；括号为空表示本示例不需要输入参数。定义到这里时不会先把三句话执行完。
- yield '先检查电源。'：把这句话交给本次取内容的循环，停在这里。循环再要下一段时，从这一行后面继续。
- 后两个 yield：依次交出第二句、第三句，每次同样暂停。
- for part in advice_parts(): 循环逐次取内容；每取到一段，用变量 part 接住，再执行下面缩进的 print。对这种包含 yield 的函数，调用 advice_parts() 本身不会把函数体全部跑完；循环开始取内容才推动它执行。
- print('收到：', part)：将本次收到的那句话显示在终端。
- 第三段打印后，循环再次取内容，函数走到末尾，没有下一段，循环结束。这里不展开内部迭代协议术语。

实际顺序：

| 轮次 | 函数本次交出的内容 | part 本次的值 | 终端输出 |
| --- | --- | --- | --- |
| 1 | 第一个 yield 的文字 | 先检查电源。 | 收到： 先检查电源。 |
| 2 | 第二个 yield 的文字 | 再检查连接线。 | 收到： 再检查连接线。 |
| 3 | 第三个 yield 的文字 | 记录具体报错。 | 收到： 记录具体报错。 |

每轮都是先交出一段、接住、打印，再取下一段；不是先把三个 yield 全执行完才开始打印。return 会结束当前函数这次执行；这里的 yield 交出一段后保留继续执行的位置。

## 第2小段：让Python持续接收模型的数据行

本段阅读位置：ticket_app/ticket_ai.py现有第36—52行。现有httpx.post是等完整响应正文接收完再返回；随后response.json读取完整内容。接下来模型请求里stream=True表示要求平台逐段发送，Python端用httpx.stream逐段读取。两处作用不同，一处告诉模型平台怎么发，一处安排本机Python怎么收。

下面是接收部分的阅读示意，位于messages定义之后。先对照理解，不把它单独替换到原函数里；原函数下方的完整response.json和return也需要同步调整，下一小段一起讲清并提供完整改法。print(line)只用于说明终端可以看见什么，后续正式代码将提取本段文字并yield。

```python
with httpx.stream(
    "POST",
    "https://api.deepseek.com/chat/completions",
    headers={"Authorization": f"Bearer {settings.ai_api_key}"},
    json={
        "model": "deepseek-flash",
        "messages": messages,
        "response_format": {"type": "json_object"},
        "thinking": {"type": "disabled"},
        "stream": True,
        "max_tokens": 800,
    },
    timeout=60.0,
) as response:
    response.raise_for_status()
    for line in response.iter_lines():
        print(line)
```

逐行职责：

- httpx.stream：本机Python通过HTTPX发起可持续读取正文的请求，不等所有正文收完才供读取。
- "POST"：仍然使用原来的POST请求方法；从httpx.post换为stream后，方法在这里明确写出来。
- URL、headers、json里的model/messages等沿用既有请求。AI_API_KEY仍由后端settings读取，不放进网页。
- "stream": True：请求模型平台在生成过程中逐段发送结果；它本身不让浏览器自动显示文字。
- with ... as response：进入这段请求，把可继续读取的响应交给response；在下面缩进代码内读取，退出with时自动关闭这个响应的读取资源。不要解释成先收完全部正文再交给response。
- response.raise_for_status()：检查HTTP响应状态，错误时抛出异常；成功HTTP状态并不证明后续完整生成或业务字段检查已成功。
- response.iter_lines()：把不断收到的响应正文按完整文本行依次交出，去掉行末换行。后续一行还未到齐时等待，直到可交出下一行或发生结束/异常。它处理的是行，不是让用户代码直接把一个网络包当成一条完整消息。
- for line in ...：每轮将本次拿到的一行保存到line；line只是变量名。
- print(line)：在运行Python的终端显示这行；此处用于看清接收内容，不负责浏览器显示。

### 同一条消息的变化

简化示例，不是本轮真实模型输出：

```text
data: {"choices":[{"delta":{"content":"先检查"}}]}
```

1. `payload = line[5:].strip()`：取第5个索引及其后面的文字，即去掉data:这5个字符；strip去掉两端空白。现在payload是一段文字：`{"choices":[{"delta":{"content":"先检查"}}]}`。
2. `data = json.loads(payload)`：读取这一条消息里的JSON，得到可按字段取值的字典。内容外观相似，但现在可执行data["choices"]。这里读取的是本条传输消息，不是对半截建议正文进行最终检查。
3. `choices = data.get("choices", [])`：取choices；如果没有这个字段，则用空列表。示例得到`[{"delta":{"content":"先检查"}}]`。

```python
    finish_reason = None

    with httpx.stream(
        "POST",
        "https://api.deepseek.com/chat/completions",
        headers={"Authorization": f"Bearer {settings.ai_api_key}"},
        json={
            "model": "deepseek-flash",
            "messages": messages,
            "response_format": {"type": "json_object"},
            "thinking": {"type": "disabled"},
            "stream": True,
            "max_tokens": 800,
        },
        timeout=60.0,
    ) as response:
        response.raise_for_status()

        for line in response.iter_lines():
            if not line.startswith("data:"):
                continue

            payload = line[5:].strip()

            if payload == "[DONE]":
                if finish_reason != "stop":
                    raise ValueError("AI建议未完整生成，请重试")
                return

            data = json.loads(payload)
            if "error" in data:
                raise ValueError("AI生成失败，请重试")

            choices = data.get("choices", [])
            if not choices:
                continue

            choice = choices[0]
            if choice.get("finish_reason") is not None:
                finish_reason = choice["finish_reason"]

    raise ValueError("AI生成连接提前结束，请重试")
```

其中分支的具体职责：

| 代码 | 当前用途 |
| --- | --- |
| finish_reason = None | 先记录“还没收到生成结束的原因” |
| not line.startswith("data:") / continue | 空行或其他非数据行，本轮跳过，循环取下一行 |
| payload == "[DONE]" | 收到了发送结束标记；它不是要显示的建议文字 |
| finish_reason != "stop" / raise | 没有正常结束的证据，不把被截断的输出当作完整成功 |
| 此处return | 结束这个逐段输出函数，退出with关闭响应；不是交出整段建议 |
| "error" in data / raise | 模型平台在数据消息里报错时结束本次生成 |
| data.get("choices", []) | 取回复列表，没有时用空列表 |
| if not choices / continue | 这条消息没有回复项，跳过；不尝试取空列表的第0项 |
| choice.get("finish_reason") is not None | 消息带了生成结束原因，保存它；stop表示正常结束，length等不算本课完整结果 |
| part = ...get("content") / if part | 取这一小段文字，只在有非空文字时交出 |
| yield part | 本次把part交给外面的循环并暂停，仍处在with里，不会因此关闭响应 |
| with外的最后raise | 如果连接已经结束却没有经过正常结束标记，就报告提前结束 |

```python
def generate_ticket_advice(ticket_text: str) -> str:
```
