## 今天的用途

Day105分清了两个软件。今天让pgAdmin找到本机的PostgreSQL，使用数据库账号建立连接，读取数据库列表。后续Day107才选择或创建学习用数据库、打开输入SQL的窗口。

在实际项目里，开发和维护人员通过管理工具查看数据库；客户一般使用工单网页。今天建立的是pgAdmin与PostgreSQL之间的连接，不代表Python后端已经接通它。

## 1. 找到连接设置

打开pgAdmin，展开左侧Servers。Servers是保存的数据库连接项目列表。

- 已有项目，例如PostgreSQL 18：右键该项目，选择Properties（属性），查看General和Connection。保留原来能用的设置；字段灰色也可以先阅读，不必为练习强制断开。
- 列表为空：右键Servers，选择Register → Server（登记一个连接项目）。这个动作只保存连接信息，不会安装新的PostgreSQL或创建新的工单数据库。

界面字段依据[pgAdmin Server Dialog官方说明](https://www.pgadmin.org/docs/pgadmin4/latest/server_dialog.html)，查看已有连接的入口依据[Connect to Server官方说明](https://www.pgadmin.org/docs/pgadmin4/latest/connect_to_server.html)。

## 2. 逐项读字段

### General → Name

这是给自己看的连接名称。例如新建项目时写“本机PostgreSQL”。已有名称可以保留。Name只是列表里的备注名称，不是数据库名称或登录账号。

### Connection → Host name/address

本课新建连接填写127.0.0.1，意思是运行pgAdmin的这台电脑本身。因为本课pgAdmin与PostgreSQL都在自己的电脑上。

已有连接如果是localhost，也是指向本机的名称，可以保留。将来数据库在另一台机器或托管平台上，应使用对方提供的连接地址，并满足相应网络与账号要求；不能把自己电脑的127.0.0.1当成远程机器。

### Port

本课是5432。地址确定哪台电脑，端口帮助连接到那台电脑上对应的程序入口。5432是本机PostgreSQL当前等待数据库连接的入口编号，数字本身不是服务器，也不是存数据的位置。

以前工单Python后端使用8001，那是另一种程序的入口，不能拿来代替这里的数据库端口。具体编号可配置，不是所有程序都固定使用课程中的数字。

### Maintenance database

默认安装通常填写postgres。这个字段决定pgAdmin建立这条管理连接时，先进入哪个已经存在的数据库；它不会替你新建库。后续课程会选择工单学习库。

### Username

按默认安装，本课使用postgres账号。它表示“以哪个数据库账号的身份连接”。如果上次明确使用了其他账号，应保留真实可用的账号，不为匹配讲义强行改名。

这里两个postgres拼写相同但用途不同：Maintenance database中的postgres是数据库名称；Username中的postgres是账号名称。

### Password

填写安装PostgreSQL时为上述数据库账号设置的密码。pgAdmin使用它向PostgreSQL验证身份。密码只在本机输入，不写进聊天或课程笔记。

如果以前保存过密码，连接时可能不再询问。这不表示PostgreSQL不验证身份。如果弹窗明确写Master Password，它是pgAdmin保护已保存密码的另一层功能，不直接等同于数据库账号密码；遇到再按具体窗口处理。[官方主密码说明](https://www.pgadmin.org/docs/pgadmin4/latest/master_password.html)

## 3. 连接并观察结果

- 如果只是查看已有项目的Properties，关闭属性窗口；未连接时右键项目，选择Connect Server，按提示在本机输入数据库账号密码。
- 如果是新建项目，填完General和Connection后点Save。默认勾选Connect now时，pgAdmin会尝试连接。
- 如果项目已经连接，继续使用已有连接，不需要为了重新学习而断开重连。

展开该项目，再展开Databases（数据库列表）。成功读取并显示其中的数据库名称、没有连接报错，是本课可观察的结果。如果列表原本已经显示，可以右键Databases选择Refresh刷新读取。仅有一个保存的项目名称，不足以证明连接成功。

如果失败，反馈具体错误文字或遮住密码后的截图。不要通过卸载、清空数据库或随意重设密码来跳过问题。

## 4. 把这次动作串起来

1. 你在pgAdmin选择保存的连接项目。
2. pgAdmin按照地址127.0.0.1和端口5432，联系本机PostgreSQL。
3. PostgreSQL按配置验证账号身份，并检查是否允许连接指定数据库。
4. 连接成功后，pgAdmin可以发送读取数据库列表的请求，并展示结果。

连接不是把数据库复制进pgAdmin；它是建立一条后续可以发送操作、接收结果的通道。

## 5. 本课小测与实际讲评（2026-09-28）

1. 在这个练习里，如果把Port从5432改成以前Python后端用的8001，即使数据库账号和密码正确，为什么也不能用这组设置连接到当前PostgreSQL？
   - 学习者回答：因为端口不对，8001是后端连接的端口。
   - 讲评：正确。更精确地说，8001是本课程之前Python后端接收网页请求的入口；5432是当前PostgreSQL接收数据库连接的入口。账号密码正确不能弥补连接目标错误。
2. Maintenance database和Username都填postgres，这两个相同的词各代表什么？Password对应的是哪个账号？
   - 学习者回答：一个代表数据库名称，一个代表用户名，密码对应Username。
   - 讲评：正确，已经分清目标数据库、登录账号及该账号的密码。
