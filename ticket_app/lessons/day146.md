## 第一小段：先认识一次请求的编号

实际作用：多人同时请求或一个页面请求多个资源时，用一个编号找准一次访问。每个新的HTTP请求由本项目代码生成新的编号；同一次请求的开始/结束/业务日志使用同一个值。编号不是员工token、工单id或镜像文件SHA256。

只查看既有main.py，不粘贴或修改：

```python
@app.middleware("http")
async def log_request(request: Request, call_next):
    request_id = uuid4().hex
    request.state.request_id = request_id
```

@app.middleware('http')登记HTTP中间件，不是启动监听；Uvicorn收到请求后，FastAPI调用已登记的函数。request是当前HTTP请求对象，call_next是框架交来的后续处理函数。uuid4()是调用随机UUID生成函数，.hex取得32字符字符串；等号保存至本次函数的request_id。request.state.request_id把同值存在当前请求的临时状态，供接收该Request的后续业务代码读取，不写数据库或磁盘文件。

继续定位同函数中的既有一行：

```python
response = await call_next(request)
```

传入当前请求、等待后续路由/依赖处理，返回响应对象，由response变量接住。对本段GET /health，FastAPI匹配get_health，函数返回Python字典，框架整理为JSON正文/status200/Content-Type等响应，随后返回到这里；框架内调用与跨SSH网络传输分开。

函数末尾既有代码：

```python
response.headers["X-Request-ID"] = request_id
return response
```

response.headers为发回浏览器的响应头集合，方括号定位X-Request-ID这个键，赋值把本次编号加入。return response交回框架/Uvicorn沿原连接发给浏览器；编号在响应头，不自动出现在health JSON正文。浏览器Headers里可能显示小写x-request-id，同一字段名大小写不影响意义。
