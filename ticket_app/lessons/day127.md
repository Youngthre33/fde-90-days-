# Day127：建立独立PostgreSQL测试数据库

## 本课目标

建立独立的ticket_app_test数据库，保证自动化测试中的新增、修改和删除不会影响日常使用的ticket_app数据库。

## 数据库分工

- ticket_app：日常业务和学习数据。
- ticket_app_test：自动化测试专用数据。

两个数据库由同一个PostgreSQL服务管理，都使用127.0.0.1:5432，但数据库名称不同，数据互相独立。

## 实际操作

在pgAdmin中创建：

`ticket_app_test`

从ticket_app_test打开Query Tool，并使用：

```sql
SELECT current_database();
确认当前数据库为ticket_app_test。
新数据库最初执行：
SELECT * FROM tickets;
返回relation does not exist，证明新数据库没有自动复制日常库的表。
随后在ticket_app_test中建立：
- public.tickets
- public.ticket_events
两张表使用与日常库相同的主键、默认值、检查规则、外键和ON DELETE CASCADE规则。
在测试库新增标题为：
Day127：只属于测试数据库
的工单，测试库查询为1行。
在日常库ticket_app查询同一标题，结果为0行，证明测试数据没有进入日常库。
回到ticket_app_test并确认current_database后，删除这张临时测试工单，再次查询为0行。
关键理解
- 5432决定连接哪个PostgreSQL服务。
- 数据库名称决定进入ticket_app还是ticket_app_test。
- 相同表名在不同数据库中代表不同的表。
- SQL注释、变量名称和文件名称不能改变实际连接目标。
- 执行清空或删除以前，应先使用SELECT current_database()确认目标。
- 测试数据库中的DELETE不会自动删除日常数据库的数据。
