## 3. 新增、取结果、提交、关闭

```python
    try:
        cursor = connection.execute(
            "INSERT INTO tickets (title) VALUES (%s) RETURNING id, title, status",
            (title,),
        )
        row = cursor.fetchone()
        connection.commit()
    finally:
        connection.close()
```

### try: 与 connection.execute

try开始使用已建立的连接。execute把SQL和参数交给PostgreSQL执行，并返回游标给cursor。INSERT是本次数据库新增动作，fetchone和print本身不负责创建。

### INSERT INTO tickets (title)

向tickets表新增一行，这次由Python明确提供title这一列。SQL里的(title)是列名列表，不是调用Python函数。

### VALUES (%s)

VALUES表示本行要填入的值，%s是Psycopg参数占位符，具体标题由execute第二项参数提供。SQL字符串里的列名title和下一行Python变量title同名，但一个指数据库列，一个保存本次输入的文字。

### RETURNING id, title, status

请PostgreSQL在新增成功后，将这张新工单的编号、标题、状态返回。这样Python能取得数据库自动产生的编号，不用猜下一号是多少，也不必再查整张表找最新一条。

这里RETURNING是SQL的一部分；它表示数据库返回哪些数据，不等于已经提交保存。Python函数中的return负责把值交给调用者，两者执行者不同。

按照本项目已建表的规则，id由数据库生成，status没有提供时使用默认open。实际编号由数据库决定，不保证连续；以真实输出为准。本课不修改表规则。

### (title,),

把本次函数参数title的值装进单元素元组，作为execute的第二项参数。例如调用create_ticket("Day118：Python新增工单")，这里提供的就是("Day118：Python新增工单",)。括号内的逗号形成单元素元组；外面的逗号结束本项调用参数。

### )

结束execute调用。查询命令与参数在这一调用中一起提供给Psycopg。

### row = cursor.fetchone()

取出RETURNING返回的一行，交给row。本例成功插入一行且带RETURNING，因此取得(id, title, status)元组。与查找工单可能没有匹配行不同，这个单行INSERT成功就会产生新增行；违反本课表的限制则报告错误，不把错误当作None成功返回。

到这里Python已经拿到了数据，但本课默认连接还没有提交；不能只因读到了id就认定已经保存。

### connection.commit()

通过当前连接提交这次修改。普通话就是：确认保存这一次新增。成功提交后，关闭本次连接，这张记录仍留在数据库里，其他连接的新查询也能查到。

本课按Psycopg默认方式使用连接：如果删掉这行，虽可能已取得RETURNING结果，随后直接关闭连接时，未提交的INSERT不会保留。commit负责本次连接里的提交，不是提交Git代码。

### finally: 与 connection.close()

finally执行关闭连接的收尾。正常顺序是INSERT → fetchone → commit → close；如果try中发生错误，也会执行close并报告错误。close只关闭连接，不替代commit，不会撤销已经成功提交的记录。本课不再引入另一套手动rollback代码，下一课用具体例子学习失败处理。

## 4. 返回字典

```python
    return {
        "id": row[0],
        "title": row[1],
        "status": row[2],
    }
```

- return {：把已经取出的数据整理成字典，交回调用者。
- "id": row[0]：把RETURNING中第一列的编号放进id字段。
- "title": row[1]：把第二列的标题放进title字段。
- "status": row[2]：把第三列的状态放进status字段。
- }：结束字典，整个字典成为函数返回值。

在本文件正常执行路径中，commit已成功、连接已关闭，然后才返回字典。字典在Python内存中，数据库记录由PostgreSQL保存；return不会再向数据库新增第二次。

## 10. 幂等性补讲（2026-09-28）

用户预测重复创建会新增两次正确，但忘记“幂等性”。解释为同一个操作用相同输入执行一次或多次，对数据的最终效果一样。本课INSERT每成功执行并提交一次就增加一行，所以是不幂等；不是“因为具有幂等性才新增两次”。假设起初10张，执行一次11张、两次12张，仅为数量示意而非实际库内统计。对照“把同一工单状态设为done”：只考虑这个状态修改，执行一次或反复设置后都为done，体现幂等；不要混入其他记录日志等副作用。

本课没有实现请求去重，不增加幂等键、重试机制或新文件。两个行为预测已正确，术语本次对照补清，不额外加题。下一步等待Python实际新增结果和pgAdmin查回同一id的结果，再收尾本课Git。
