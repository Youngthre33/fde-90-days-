## 1. 今天解决什么问题

## 2. 操作前的重要边界

当前GET列表默认按id升序只取第一页10张。新增成功后，main.js会把新工单追加到浏览器当前数组，所以页面可能临时显示11张；整页刷新后，网页重新取得最早10张，新编号可能不在第一页，因此可能暂时看不到。

这不代表新工单被删除，也不代表保存失败。今天用pgAdmin按唯一练习标题查回记录，作为数据库保存证据；不为了本课顺便修改分页规则。

同一个标题可以重复保存，普通INSERT没有自动去重。操作时只点击一次“添加工单”。

## 5. 第二小段：发送带JSON正文的POST

```javascript
        const response =
            await fetch(
                TICKETS_API_URL,
                {
                    method: "POST",
                    headers: {
                        "Content-Type":
                            "application/json"
                    },
                    body:
                        JSON.stringify(
                            ticketToCreate
                        )
                }
            );
```

- `fetch(...)`由浏览器发送HTTP请求。
- `TICKETS_API_URL`当前是`http://127.0.0.1:8001/tickets`，所以请求直接发给8001后端。
- 第二个参数大括号里放这次请求的具体设置。
- `method: "POST"`告诉后端这次要提交一份用于创建的数据；不写时fetch默认是GET。
- `headers`放请求的说明信息。
- `"Content-Type": "application/json"`告诉后端：请求正文使用JSON格式。
- `body`是请求正文，即真正随请求发送的数据内容。
- `JSON.stringify(ticketToCreate)`把JavaScript对象转换成JSON文字。上面的对象会变成`{"title":"Day122：网页新增工单"}`。
- `await`让本函数等待后端响应，再把完整HTTP响应对象交给`response`。

`response`里包含状态码、响应头和响应正文；它此时还不是新工单对象。

## 6. 8001后端怎样接住标题

`ticket_app/main.py`：

```python
class TicketCreate(BaseModel):
    title: str = Field(min_length=1, pattern=r"\S")
```

- `TicketCreate`描述创建请求允许有什么内容。
- `title: str`要求title必须是字符串。
- `min_length=1`不接受长度为0的空字符串。
- `pattern=r"\S"`要求内容里至少有一个非空白字符，因此只输入空格也不能通过。

POST入口：

```python
@app.post(
    "/tickets",
    response_model=Ticket,
    status_code=201,
)
def create_ticket(ticket_to_create: TicketCreate):
    created_ticket = create_new_ticket(
        ticket_to_create.title
    )

    return created_ticket
```

- `@app.post("/tickets", ...)`把POST `/tickets`登记给下面的函数处理。
- `response_model=Ticket`规定成功返回的工单包含id、title和status。
- `status_code=201`表示成功创建新资源时返回HTTP 201。
- `ticket_to_create: TicketCreate`让FastAPI先按上面的规则检查请求JSON，再把合格结果交给变量。
- `ticket_to_create.title`取出浏览器发来的标题。
- `create_new_ticket(...)`把标题交给service；service再交给repository。
- `created_ticket`接住数据库层返回的完整新工单。
- `return`把完整新工单交给FastAPI，FastAPI把它做成HTTP响应返回浏览器。

如果标题不合格，FastAPI在进入数据库写入前返回422，repository不会执行INSERT。

## 7. PostgreSQL在哪一行真正保存

`ticket_app/ticket_service.py`：

```python
def create_new_ticket(title: str):
    return ticket_repository.create_new_ticket(title)
```

service接到标题，再调用repository的同名函数；repository才负责SQL。

`ticket_app/ticket_repository.py`：

```python
def create_new_ticket(title: str):
    with get_connection() as connection:
        cursor = connection.execute(
            "INSERT INTO tickets (title) VALUES (%s) "
            "RETURNING id, title, status",
            (title,),
        )
        row = cursor.fetchone()

    return row_to_ticket(row)
```

- 函数收到service传来的标题。
- `get_connection()`使用配置连接5432后面的PostgreSQL，`connection`指向本次连接对象。
- `with`中的步骤全部正常完成时提交本次INSERT，退出时关闭本次连接；发生数据库错误时撤回本次尚未提交的修改并关闭连接。
- `INSERT INTO tickets (title)`说明本次只给title列提供值。
- `%s`是SQL参数位置；`(title,)`把真实标题安全地交给这个位置。单元素元组需要逗号。
- `RETURNING id, title, status`要求PostgreSQL在新增后把完整那一行返回。
- `cursor`接住SQL执行结果入口。
- `fetchone()`从这次RETURNING结果中取出新增的一行。
- `row_to_ticket(row)`把数据库行整理成含id、title和status的Python字典，再逐层返回。

表结构里的两条规则：

```sql
id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
status TEXT NOT NULL DEFAULT 'open'
```

因此浏览器只发送title时：

- `id`由PostgreSQL的identity规则产生；
- `status`由PostgreSQL的默认值规则填成`open`；
- 不是main.js猜出id，也不是FastAPI响应模型凭空补上status。

## 8. 第三小段：浏览器取得完整新工单

```javascript
        if (!response.ok) {
            throw new Error(
                `HTTP状态码:${response.status}`
            );
        }

        const createdTicket =
            await response.json();
```

- `response.ok`在状态码200—299时为true；本次成功201也属于这个范围。
- `!response.ok`表示响应不成功。
- 不成功时主动产生错误，停止try后续步骤并进入catch。
- 成功时`response.json()`读取响应正文，把JSON转换成JavaScript对象。
- `createdTicket`接住单个完整对象，例如`{id: 14, title: "Day122：网页新增工单", status: "open"}`。实际id以数据库生成值为准。

Day121的GET列表解析出“工单数组”；Day122的POST只创建一张，因此这里解析出“一个工单对象”。

## 9. 第四小段：追加到浏览器数组并显示

```javascript
        const newTickets = [
            ...tickets,
            createdTicket
        ];

        setTickets(newTickets);

        render(
            newTickets,
            editingId
        );

        ticketInput.value = "";
```

- 方括号创建一个新数组。
- `...tickets`把浏览器当前数组里的每张工单依次放进新数组。
- `createdTicket`放在末尾，因此新数组比原数组多一张。
- `setTickets(newTickets)`让浏览器内存中的tickets指向新数组；它不负责数据库INSERT，因为数据库已经在后端返回响应前保存完成。
- `render(...)`把新数组重新画到页面上。
- `ticketInput.value = ""`把输入框内容清空，表示本次成功操作已完成。

## 14. 第一轮理解题答案与讲评（2026-09-28）

学习者原答：“是Postgream产生的默认值，ticket_repository里的数据库命令才是真正的保存在了数据库里，INSERT INTO tickerts(title) VALUES。2不能，把显示的限制条件limt改成20再刷新显示。”

第1题核心方向正确：应为PostgreSQL；id来自identity规则，status的open来自DEFAULT规则。repository里的`INSERT INTO tickets (title) VALUES (%s)`是真正要求数据库新增的SQL。需要补精确边界：INSERT先在本次事务中产生修改，repository的数据库`with`正常退出时提交，提交后才成为正式保存；`RETURNING`和`fetchone`只负责取回新增结果，不代替提交。原答中的`tickerts`是拼写口误，真实表名是`tickets`。

第2题“不能证明新增失败或被删除”的结论正确。把limit改为20在浏览器实际发出该查询条件、且目标记录落入这20条时可以重新显示，但当前main.js没有发送limit=20，只说“改成20”不会改变现有请求；而且列表显示仍是筛选结果，不是最直接的持久化证据。本课最准确的方法是在pgAdmin执行`SELECT id, title, status FROM tickets WHERE id = 15;`，或用单张接口GET `/tickets/15`。

学习者随后确认在pgAdmin查到`id=15`记录，完成亲自查询证据。结合页面三个结果、教师独立只读核对和两题回答，Day122实操与核心理解通过。下一课Day123只学习网页修改标题和状态，分别追踪PATCH、UPDATE和返回结果，不重复新增流程。
