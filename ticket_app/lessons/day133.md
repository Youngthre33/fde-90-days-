# Day133：用版本条件阻止旧内容覆盖新内容

## 本课目标与当前范围

继续 Day132 的两个操作者练习，仅在 pgAdmin 的 `ticket_app_test.public.tickets` 中给工单增加 `version`，并使用编号与版本共同限制 UPDATE。`id` 确定哪张工单，`version` 表示这张工单的当前版本。版本不会因标题修改自动增加，后续 SQL 须明确写 `version = version + 1`。

本课是数据库层实验。当前应用源码、API 和网页尚未加入版本处理；实验成功不等于网页已经具有防覆盖功能。

## A 先保存，B 旧版本被挡住

已要求 A、B 各自读取 5 号工单的版本 1，随后只在 A 执行：

```sql
UPDATE public.tickets
SET title = 'Day133: A补充',
    version = version + 1
WHERE id = 5 AND version = 1
RETURNING id, title, version;
```

逐行讲解两个 SET 赋值、AND 同时检查编号与版本、先匹配 WHERE 再修改，以及 RETURNING 返回实际更新的行。A 的单独返回结果未贴出；学习者说“继续B窗户 这里我理解了”，随后在 B 继续使用旧版本 1：

```sql
UPDATE public.tickets
SET title = 'Day133: B补充',
    version = version + 1
WHERE id = 5 AND version = 1
RETURNING id, title, version;
```

此时数据库的版本已是 2，没有行同时满足编号 5、版本 1，SET 没有行可修改，返回 0 行。然后重新 SELECT 5 号，预期仍为 `Day133: A补充`、版本 2。学习者明确回复“确认了 继续”，报告 B 更新返回 0 行和复查仍为 A 标题、版本 2；未贴截图或逐项输出，教师未操作数据库。0 行来自条件不匹配，本次没有通过回滚撤销一次已经执行的修改。

## B 重新读取后补充保存

已要求 B 重新 SELECT 5 号，看到 `Day133: A补充`、版本 2，再保存：

```sql
UPDATE public.tickets
SET title = 'Day133: A补充 + B补充',
    version = version + 1
WHERE id = 5 AND version = 2
RETURNING id, title, version;
```

已逐行解释版本 2 来自 B 的最新读取，标题由操作者决定怎样组合，PostgreSQL 不自动合并文字；成功修改时版本加至 3，并要求再 SELECT 核对。学习者回复“是的 版本3了 继续”，报告该保存与复查符合预期、版本为 3，未贴逐列输出或截图，教师未操作数据库。

## 关键理解题与实际讲评

1. 当前标题为 `Day133: A补充 + B补充`、版本 3，旧页面使用 `WHERE id = 5 AND version = 2` 保存。学习者回答“0行，还是原来的，因为 WHERE 要求 version 2，当前是3，所以找不到，没法UPDATE”。结果与理由均正确：无行满足条件，RETURNING 返回 0 行，标题不变、版本仍为 3。
2. A、B 都读到版本 3，A 保存并提交了新标题但遗漏版本加一；B 未刷新，随后用版本 3 保存。学习者回答“能保存成功，因为A之后版本还是3，所以B的WHERE可以选到，所以能够改了覆盖掉A的修改”。结果与理由均正确：A 未递增版本，B 的旧版本条件仍匹配。使用本课这种保护规则时，每次成功修改必须同时递增版本。

两道关键理解题已通过，不追加重复测验。版本条件和成功修改后的版本加一须一起使用。重新读取后，操作者仍须根据最新内容决定要保存的标题；数据库不会自动合并文字。
