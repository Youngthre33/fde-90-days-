## 为什么用公网IP证书

Let’s Encrypt在2026-01-15正式提供公网IP证书，要求shortlived profile，证书有效160小时，必须自动续期。Caddy2.11系列已支持，官方stable安装避免Ubuntu旧包拒绝IP。IP默认内部CA不能让普通浏览器直接信任，所以明确指定Let’s Encrypt ACME issuer与shortlived；不用忽略证书错误或明文HTTP传员工token。

只查看入口配置：

```caddyfile
{
    default_sni 42.192.114.83
}

42.192.114.83 {
    tls {
        issuer acme https://acme-v02.api.letsencrypt.org/directory {
            profile shortlived
        }
    }
    reverse_proxy 127.0.0.1:8002
}
```

外层IP指定这个站点的公开地址；tls是浏览器到Caddy的HTTPS设置，issuer指定申请证书的机构接口，shortlived是IP证书类型，不是员工登录token。default_sni为无SNI的IP访问指定证书选择默认值：云网卡可能只有10.0.0.8私网地址，不能按本地私网IP误选证书。reverse_proxy由Caddy在服务器执行，127.0.0.1指上海服务器自身，8002由Docker转给api内Uvicorn8001；请求路径如/web/和/tickets保留。

网页仍由main.py的app.mount读取web/index.html，浏览器按script加载main.js及模块并在Windows执行。constants.js的/tickets从当前https://42.192.114.83/web/解析为https://42.192.114.83/tickets；fetch带Authorization交Caddy→Docker→Uvicorn/FastAPI→auth.py认证/权限→main.py业务路由→service→repository→PostgreSQL。数据沿函数return回路由/框架JSON→Caddy HTTPS响应→原fetch的await→response.json→页面渲染。认证与数据存放位置不因为入口改变而换到Caddy或浏览器。
