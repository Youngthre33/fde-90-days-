## 2. 导入、定义函数与建立连接

```python
import psycopg

from ticket_app.config import settings
```

第一行提供数据库连接工具；第二行取得现有配置，仍与前课相同。

```python
def find_ticket_by_id(ticket_id):
    connection = psycopg.connect(
        host=settings.db_host,
        port=settings.db_port,
        dbname=settings.db_name,
        user=settings.db_user,
        password=settings.db_password,
        connect_timeout=5,
    )
```

- def：定义一个函数。Python读到定义时准备好这项功能，不会立刻运行函数体去连接数据库。
- find_ticket_by_id：我们起的函数名，含义是按编号查找工单。函数名与文件名是两件事。
- (ticket_id)：定义这个函数要接收的参数名。调用find_ticket_by_id(3)时，这次调用里的ticket_id得到3；不是从输入框自动读，也不是每次固定3。
- 冒号：后面缩进的内容属于函数。函数体内的connection、cursor、row是这次调用使用的局部变量。
- connection = psycopg.connect(：真正调用函数后才执行，建立本次连接，用connection接住返回的连接对象。
- host=settings.db_host：从配置取数据库服务地址。
- port=settings.db_port：从配置取数据库服务端口，当前为5432。
- dbname=settings.db_name：指定数据库名称。
- user=settings.db_user：提供账号。
- password=settings.db_password：提供账号密码，仍由现有配置读取。
- connect_timeout=5：连接等待限制。
- )：结束connect调用。

原先文件顶层的ticket_id = 3不再需要。本次输入来自最下方调用时写的find_ticket_by_id(3)。定义里的参数名负责接收调用者提供的值。

## 3. 函数里面仍执行熟悉的查询

下面这些行保持在函数缩进内：

```python
    try:
        cursor = connection.execute(
            "SELECT id, title, status FROM tickets WHERE id = %s",
            (ticket_id,),
        )
        row = cursor.fetchone()
    finally:
        connection.close()
```

- try：开始使用已建立的连接查询，finally负责收尾；连接建立本身在try前。
- cursor = connection.execute(：发送SQL和参数，把返回的查询结果读取对象交给cursor。
- SQL字符串：取id、title、status三列，只筛选id等于提供参数的行。
- (ticket_id,)：把函数本次收到的编号，以单元素元组提供给SQL。例如这次参数是3，此处是(3,)；括号内逗号保留。
- )：结束execute调用。
- row = cursor.fetchone()：取得一行元组或None，交给row。若SQL/连接出错会抛出异常，不会自动转成None。
- finally：无论try中成功或异常，都执行收尾。
- connection.close()：关闭本次连接。

这里关闭连接后，已经取到的row仍是Python内存里的值。例如row可能是(3, '打印机故障', 'open')。关闭联系数据库的连接，不会把这个值擦掉，所以后面仍可用row整理结果。本例三列为整数和文本，不是还需连接才能读取的外部数据句柄。

## 4. 没找到时提前返回

```python
    if row is None:
        return None
```

- if row is None：检查刚才是否没有取到一行。is None是判断，区别于赋值等号。
- return None：把None交给调用这个函数的位置，并结束这次函数执行。

执行了return None，就不会继续执行下面的字典代码。否则对None执行row[0]会报错，因为None没有第一个、第二个字段可取。

此处None表示这次成功查询没有匹配行。它不表示数据库连接失败，也不表示数据库里所有工单都没了。

## 5. 找到时把一行整理成字典返回

```python
    return {
        "id": row[0],
        "title": row[1],
        "status": row[2],
    }
```

- return {：开始创建一个字典，并将整个字典返回给调用者。字典用字段名对应各个值。
- "id": row[0]：从row的第一个位置取编号，放到字典的id字段。Python从0开始计数。
- "title": row[1]：从第二个位置取标题，放到title字段。
- "status": row[2]：从第三个位置取状态，放到status字段。
- 每行冒号左边是字段名，右边是要放进去的值；逗号隔开字典里的不同项目。
- }：结束字典内容，整个字典作为这次函数调用的返回值。

这三个位置由SQL的SELECT id, title, status顺序决定。row[0]中的0是位置，不是数据库编号0；row[1]也不是查询编号1。

假设row为(3, '打印机故障', 'open')，返回值是：

```python
{
    "id": 3,
    "title": "打印机故障",
    "status": "open",
}
```

这里只在Python内存里整理一份数据，不修改数据库表结构或记录。后续代码可用ticket["title"]按名称读取标题，比到处记第二个位置表示什么更直观。

## 6. 文件底部：真正调用函数

```python
if __name__ == "__main__":
    ticket = find_ticket_by_id(3)
    print("查询结果：", ticket)
```

- if __name__ == "__main__": 回顾之前的运行入口判断。通过python -m ticket_app.find_ticket运行本文件时，这个条件成立，执行缩进的两行。以后别的文件导入这个函数时，不自动执行这里的示例查询。双下划线及拼写保持原样，==是相等判断。
- ticket = find_ticket_by_id(3)：先执行右边的函数调用；3传给函数参数ticket_id。等函数执行完return，再把返回的字典或None交给外面的ticket变量。
- print("查询结果：", ticket)：打印调用结果。这时查询函数已返回，函数里的连接已关闭。

函数内部的return把结果交给调用它的Python代码；print负责在终端显示。return本身不打印、不自动发送网页响应。

这里的ticket和函数内部的ticket_id不是同一个变量：ticket_id是要查的输入编号，ticket是调用后收到的字典或None。

## 7. 一次完整执行顺序

读取导入与函数定义 → 到底部运行入口 → 调用find_ticket_by_id(3) → 函数参数ticket_id收到3 → 连接数据库 → 用(3,)查id → fetchone得到row → finally关闭连接 → 如果row为None就返回None，否则创建字典返回 → 外面的ticket接住返回值 → print显示。

连接关闭发生在本例整理字典和return之前；已经拿到的Python值仍可使用。函数的每次调用都有自己的参数值与局部变量，连接也在本次调用中创建和关闭。
