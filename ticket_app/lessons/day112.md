每次选中当前完整的一条SQL执行。先只运行下面的新增语句一次：

```sql
INSERT INTO tickets (title)

RETURNING id, title, status;
```

- 第一行：向tickets表新增一行，这次明确提供title。

- 第三行：返回这次实际新增的编号、标题和状态；分号结束语句。

## 3. 删除前核对目标

```sql
SELECT id, title, status
FROM tickets
WHERE id = 27;
```

第一行指定读取的三列，第二行指定工单表，第三行只查询指定编号。确认结果的id正是刚才返回的编号，标题是“Day112：删除练习工单”。

这一步完成“要删除的是哪张”的核对。没有查到或内容不符时，先检查编号和目标库，不继续执行删除。

## 4. 逐行理解并执行删除

```sql
DELETE FROM tickets
WHERE id = 27
RETURNING id, title, status;
```

第一行DELETE FROM tickets：从tickets表删除记录。DELETE删除的是符合条件的整行记录；该行的id、title和status一起不再出现在这张表里，表本身与列定义仍在。

第二行WHERE id = 27：限定本次删除的目标，等号判断编号是否相等。id是主键，本课这个条件最多选中一张工单；其他tickets行不由这条条件选中。[官方DELETE说明](https://www.postgresql.org/docs/current/sql-delete.html)

第三行RETURNING id, title, status：把本次实际被删除的记录原来的编号、标题和状态交回pgAdmin。可以把它理解为本次删除操作的回执，用来告诉你刚删的是哪一张；不是再次查询当前表，也不是说该行仍保存在表里。这里只返回结果，没有自动创建历史记录表。[官方RETURNING说明](https://www.postgresql.org/docs/current/dml-returning.html)

RETURNING不负责提交；本课Auto commit开启，成功的删除会自动提交。

确认真实编号后，选中完整三行执行一次。Data Output预期显示这次删除记录原来的字段值。

## 5. 删除后重新查询

用相同的真实编号执行：

```sql
SELECT id, title, status
FROM tickets
WHERE id = 27;
```

三行仍然是“读取三列、从工单表、按指定编号”。预期返回0行，表示现在找不到这一条；列名可能仍显示，不表示有一条空记录。不是整张表不存在。

再查询当前工单表：

```sql
SELECT id, title, status
FROM tickets
ORDER BY id;
```

第一行指定三列，第二行从tickets读取，第三行将结果按编号从小到大排列。这条查询没有筛选条件，所以查看当前全部工单。应能看到其余原有tickets记录仍在；本课的练习编号不再出现，表仍可以正常查询。若删除前只有本课这一行，查询全部也会返回0行，但表仍然存在。

## 6. 分清三种结果

| 操作 | 数据行的结果 | 表的结果 |
| --- | --- | --- |
| DELETE按编号删一条 | 指定行消失 | 表、列定义保留 |
| DELETE成功删除全部行 | 没有任何数据行 | 是一张空表，仍可查询或新增 |
| 删除整张表 | 表及其数据不再作为原表存在 | 按原表名查询会报表不存在 |

DELETE不带WHERE时会删除表中的全部行，但留下表本身。这里只解释区别，不执行全表删除或删除表。[DELETE的范围](https://www.postgresql.org/docs/current/sql-delete.html)；[PostgreSQL表基础说明](https://www.postgresql.org/docs/current/ddl-basics.html)

流程：pgAdmin发出带真实编号条件的DELETE → PostgreSQL删除匹配的工单行 → 返回这次被删行的原内容，并在本课自动提交设置下保存删除 → pgAdmin显示回执 → 再次SELECT按同一编号查询 → 返回0行。

Day109新增、Day110查询、Day111修改、Day112删除，这四项合起来就是常见的“增查改删”。目前练习入口是pgAdmin；后续会让Python程序发出这些数据库命令。

## 7. 两道理解题

1. 删除成功后，RETURNING在pgAdmin中显示了刚才那张工单的编号和标题，但你再按相同编号SELECT却查到0行。这两种结果矛盾吗？它们分别告诉你什么？
2. 假设这条DELETE只去掉WHERE条件，成功执行并自动提交后，tickets表里所有记录被删除。此时再次SELECT读取tickets，应当返回0行，还是报“表不存在”？为什么？只回答，不执行这一操作。
