## 3. 第一段：沿用上一课的连接

```python
import psycopg

from ticket_app.config import settings

connection = psycopg.connect(
    host=settings.db_host,
    port=settings.db_port,
    dbname=settings.db_name,
    user=settings.db_user,
    password=settings.db_password,
    connect_timeout=5,
)
```

- `import psycopg`：让本文件可以使用已经安装的PostgreSQL连接工具。
- `from ticket_app.config import settings`：取得config里准备好的配置对象settings。
- `connection = psycopg.connect(`：调用connect建立一次新连接，把返回的连接对象交给connection这个变量。每次运行本文件都会重新执行这里，不是借用上一课已经关闭的连接。
- `host=settings.db_host`：把配置中的地址交给host，指出数据库服务在哪台电脑。
- `port=settings.db_port`：把配置中的目标端口交给port；当前是PostgreSQL的5432入口。
- `dbname=settings.db_name`：指定要连接的数据库，当前为ticket_app。
- `user=settings.db_user`：指定数据库登录账号。
- `password=settings.db_password`：提供该账号的密码，由已有配置读取。
- `connect_timeout=5`：设置建立连接的等待上限为5秒，不是让整段程序运行5秒。
- `)`：结束connect的参数列表和调用。参数行中的等号表示把右边的值交给左边所命名的参数；最外面的connection等号表示把调用结果赋给变量。

## 4. 第二段：查询、取结果、显示、关闭

```python
try:
    cursor = connection.execute(
        "SELECT id, title, status FROM tickets ORDER BY id"
    )
    rows = cursor.fetchall()
    print("查询结果：", rows)
finally:
    connection.close()
```

### try:

下面缩进的内容是连接建立之后要做的事情，结束后由finally收尾。try不会自动把错误变成成功。connect在try之前，若连接本身失败，就不会进入这里。

### cursor = connection.execute(

- connection：刚刚建立的这一次数据库连接。
- 点号：使用这个连接对象提供的execute方法。
- execute：通过连接发送括号里的SQL，让PostgreSQL执行。
- 括号：调用这个方法，并在里面提供要执行的SQL文字。
- `cursor =`：把execute返回的Cursor对象交给变量cursor。

Cursor中文常叫“游标”。在这段代码里，可以把它理解为“用来读取本次查询结果的工具”。它是Python程序中的对象，不是数据库里的表，也不是已经整理好的工单列表。变量名cursor是我们起的名字，返回对象的能力来自psycopg。

connection.execute会创建一个游标、执行SQL，再返回这个游标。本行成功返回时，SQL已经执行，不是等到fetchall才开始查询。

### "SELECT id, title, status FROM tickets ORDER BY id"

双引号表示这一段是Python字符串，也就是要交给数据库的文字指令。PostgreSQL收到后按SQL理解并执行：

- SELECT id, title, status：取编号、标题、状态这三列。
- FROM tickets：从tickets这张表中取。
- ORDER BY id：按编号从小到大排列；默认升序。

这条语句没有WHERE，因此查询这张表里当前可见的全部工单。排序只规定本次结果的顺序，不会改变工单编号、标题、状态。

下一行的`)`结束execute调用。分成三行是为了阅读方便，它们合起来是一次调用。

### rows = cursor.fetchall()

- cursor：上一行得到的读取结果工具。
- fetchall：取出本次查询中还没有取出的全部结果行，并返回一个Python列表。
- `()`：调用fetchall。本次无需再传表名或SQL，因为cursor已经对应刚才的查询。
- `rows =`：把返回的列表交给rows，rows这个英文名表示“多行”。

本例之前没有取过结果，所以这里取得全部查询结果。不要把fetchall理解成再次发送SELECT，也不要理解成从数据库删除记录。

### print("查询结果：", rows)

print把提示文字和rows里的数据一起显示在运行Python的终端里。逗号隔开传给print的两项内容；这一步不会自动把数据送到浏览器。

### finally: 和 connection.close()

try里的查询和打印结束后，finally负责运行close关闭这一次连接；即使try中报错，也执行这个收尾。错误不会因此被消除。PostgreSQL服务和pgAdmin的独立连接继续保持各自的状态。

这里仅运行普通SELECT读取工单，没有新增、修改或删除，因此没有写入需要commit保存。

## 5. 怎样看打印结果

下面是假设库中有两张工单的格式示例，不是实际查询证据：

```text
查询结果： [(3, '打印机故障', 'open'), (7, '网络连接失败', 'done')]
```

- 外面的`[...]`是Python列表，里面可以有多行结果。
- 每个`(...)`是一行，这种按位置放值的结构叫元组。
- 每行三个位置依次对应SELECT里的id、title、status。
- 例如`(3, '打印机故障', 'open')`表示编号3、标题为打印机故障、状态为open。
- 实际编号、标题、条数以自己的数据库内容为准，不要求和例子相同。

若表存在而本次查询没有符合条件的行，fetchall返回空列表`[]`。空结果和连接失败、表不存在等报错要分开判断。

### 与fetchone作一个小对照

本文件运行的是fetchall，暂时不需要改代码。对同一条刚执行完、还没取过数据的查询：

| 方法 | 取什么 | 没有可取结果时 |
| --- | --- | --- |
| cursor.fetchone() | 下一行；第一次调用取得查询结果的第一行 | None |
| cursor.fetchall() | 还没取出的全部行，放进列表 | [] |

本SQL有ORDER BY id，所以第一次fetchone会取得查询结果中编号最小的那一行，不是随机选取。多次fetch会继续向后取，不会每次自动从头开始；本课脚本只调用一次fetchall。
