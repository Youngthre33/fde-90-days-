# 当前工单 API：请求与回复示例

后端基础地址：`http://127.0.0.1:8001`，实际程序为 Day90。
API 是程序之间约定的操作入口：请求方法说明要做什么，路径说明操作哪个资源，JSON 正文携带要提交的数据。
当前示例供浏览器页面、Swagger 或其他调用程序参考；浏览器地址栏直接打开链接只能方便地执行GET，创建／修改／删除请使用Swagger或对应程序代码。

## 接口总表

| 方法与路径 | 做什么 | 输入 | 成功回复 |
| --- | --- | --- | --- |
| GET `/health` | 检查服务能否回复 | 无 | 200，`{"status":"ok"}` |
| GET `/tickets` | 查询工单列表 | 可选status、limit | 200，工单数组；无结果时为 `[]` |
| GET `/tickets/{ticket_id}` | 查询一个工单 | 正整数编号 | 200，一个工单对象 |
| POST `/tickets` | 创建工单 | JSON中的title | 201，新工单对象 |
| PATCH `/tickets/{ticket_id}` | 修改部分字段 | 编号、JSON中的title或status | 200，修改后的完整工单 |
| DELETE `/tickets/{ticket_id}` | 删除工单 | 正整数编号 | 204，没有响应正文 |

完整工单包含 `id`、`title`、`status`。请求中的编号和回复中的编号应以实际值为准，不保证每次创建得到同一个编号。

## 示例一：筛选并限制数量

```http
GET /tickets?status=open&limit=2
```

含义：最多返回两条待处理工单。limit默认10，允许1到100；status可以省略，指定时只能是open、in_progress或done。
返回内容取决于当前后端内存，可以少于两条。

## 示例二：创建一条专用练习工单

在Swagger展开 `POST /tickets`，点击Try it out，将请求正文填写为：

```json
{
  "title": "Day92示例：打印机无法连接网络"
}
```

点击Execute后，成功状态码为201。下面只是形状示例，其中105不是固定结果：

```json
{
  "id": 105,
  "title": "Day92示例：打印机无法连接网络",
  "status": "open"
}
```

后端生成编号并设置初始open，调用方只需提供标题。后续查询、修改、删除请使用这次实际返回的编号，只操作自己的练习记录。

## 示例三：修改标题或状态

展开 `PATCH /tickets/{ticket_id}`，点击Try it out，填入实际编号。
只修改标题时，正文为：

```json
{
  "title": "Day92示例：已确认是网络设置问题"
}
```

只修改状态时，正文为：

```json
{
  "status": "in_progress"
}
```

成功返回200与完整工单。只发title会保留原状态，只发status会保留原标题；两个字段也可同时提交。
网页规定状态依次为open → in_progress → done → open；当前后端只检查值是否属于这三种，不强制调用方按这个顺序变更。
当前PATCH会忽略未提供或显式为null的字段，因此空对象或null字段不表示清空标题。

## 示例四：删除

展开 `DELETE /tickets/{ticket_id}`，填入自己的练习工单编号并Execute。
成功返回204，没有JSON正文。之后GET该编号应为404，列表也不再包含它。

## 错误回复如何理解

| 情况 | 状态码 | 解释 |
| --- | --- | --- |
| 查询、修改、删除不存在的正整数编号 | 404 | 这个操作入口存在，但对应工单不存在 |
| 将编号填成0或abc | 422 | 编号不符合正整数要求 |
| 创建时缺少title或提交 `"title":""` | 422 | 必填标题缺失，或标题长度不足1 |
| 修改时提交 `"status":"unknown"` | 422 | 状态不属于允许值 |
| limit为0或101 | 422 | 条数超出允许范围 |
| 程序出现未处理异常 | 500 | 查看后端终端追踪；不能直接认定为CORS错误 |

工单不存在时的正文：

```json
{
  "detail": "工单不存在"
}
```

422的detail通常是错误列表，含出错位置与原因，应以实际回复为准。
`status: "done"`是工单处理状态，HTTP 200／404是这次请求的结果，两者不是同一个字段。

## 去哪里找请求编号和日志

正常返回及常见404／422回复会经过当前日志中间件，响应头包含 `X-Request-ID`。它不在工单JSON正文中。
后端终端记录请求编号、方法、路径、状态码和耗时；遇到未处理异常则记录错误追踪。当前500异常路径不保证有自定义编号响应头。
当前网页CORS配置允许来自 `http://127.0.0.1:5500` 的脚本读取回复与这个编号头。
