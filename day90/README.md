# Day 90：通过网页创建和删除 Python 后端工单

## 今天解决什么问题

客户填写问题并点击提交，后端创建记录，网页显示新工单；客户删除记录，后端实际删除，网页同步移除。
Day 89 已经接通读取；Day 90 接通创建和删除；接下来的 Day 91 核对编辑标题和推进处理状态。
这些课程合起来，让客户可以通过网页操作自己的 Python 工单系统。之后接数据库解决长期保存，再学习部署供客户访问。

## 谁在做什么

| 角色 | 真实工作 |
| --- | --- |
| 客户的浏览器 | 接收输入和点击，运行 JavaScript，发送请求并展示结果 |
| 5500 的网页文件服务 | 将 HTML 和 JavaScript 文件交给浏览器，不转发工单请求 |
| 8001 的 Python 后端 | 接收请求，检查输入，执行查询、创建、修改和删除 |
| 两个终端 | 供开发者启动程序、查看日志；客户通常不用操作 |

5500、8001 是服务接收请求的入口编号。当前两个服务都在自己的电脑上，`127.0.0.1` 表示访问者自己的设备。

## 启动与访问

在仓库根目录的后端终端停止之前的后端，再执行：

```powershell
.\.venv\Scripts\python.exe -m day90.run
```

当前配置的端口是 8001，以启动日志为准。另一个终端提供网页文件：

```powershell
.\.venv\Scripts\python.exe -m http.server 5500 --bind 127.0.0.1
```

已有 5500 服务可继续使用，不要重复启动。打开 `http://127.0.0.1:5500/day90/index.html`。
网页来源仍是 `http://127.0.0.1:5500`，继续使用复制过来的 CORS 配置。

## 创建一次工单的完整流程

```text
客户填写标题，点击“添加工单”
  → handleAddTicket 读取输入，暂时禁用添加按钮
  → JSON.stringify 把只有 title 的对象转成 JSON 文本
  → fetch 向 8001 发送 POST /tickets
  → FastAPI 根据 TicketCreate 检查输入，创建参数对象
  → create_ticket 将标题传给 create_new_ticket
  → 后端生成编号、设置 open 状态，append 到内存中的 tickets
  → 返回完整工单，FastAPI 生成 201 和 JSON 回复
  → 浏览器检查 response.ok，用 response.json() 读取新工单
  → 把新工单加入浏览器数组，setTickets 并 render
  → 清空输入框，finally 恢复添加按钮
```

网页发送标题，后端决定编号和初始状态。删掉请求里的 `status` 不会让工单缺少状态。
浏览器是在收到成功回复后才显示新增记录；仅在网页中增加一行，并不代表后端数据已经改变。

## 删除一次工单的完整流程

```text
客户点击某条记录的“删除”
  → 点击处理代码读取该条工单编号，暂时禁用删除按钮
  → fetch 向 8001 发送 DELETE /tickets/编号
  → FastAPI 检查编号，路由调用 delete_ticket_by_id
  → 后端找到对应字典，从内存 tickets 列表 remove
  → 路由回复 204，响应正文为空
  → 浏览器检查 response.ok，不调用 response.json()
  → deleteTicket 过滤掉浏览器数组中的对应记录
  → setTickets 并 render，finally 恢复按钮
```

业务函数返回被删除的对象，供路由判断是否找到；路由选择用 204 告诉请求方删除成功，不发送工单正文。
如果编号不存在，后端返回 404，浏览器不会继续执行成功后的本地删除。

## 一次核对创建和删除

浏览器按 F12 打开 Network／网络，查看 Fetch/XHR 请求，可在标头中看到请求方式和状态码。

| 操作 | 应看到的结果 | 实际证明什么 |
| --- | --- | --- |
| 新增一条专用测试工单 | POST 返回 201，网页出现待处理工单 | 后端接受标题并创建记录 |
| 点击重新加载 | 新工单仍在 | GET 能从后端重新取得它 |
| 删除刚新增的测试工单 | DELETE 返回 204，网页移除记录 | 后端执行删除 |
| 再次重新加载 | 被删记录不再出现 | 后端当前数据也已改变 |

浏览器可能自动发出 OPTIONS 跨来源预检，由 CORS 组件处理，无需手动添加 OPTIONS 路由。
学习者按上述新增、重新加载、删除、再重新加载的整组步骤操作后，反馈“可以了”，确认网页操作正常；没有据此额外声称其逐项报告了 Network 中的状态码。
助手已在独立测试进程对实际 Day90 后端验证创建 201、查询取回、删除 204 空正文、随后查询 404、空列表创建和删空再创建、空标题 422，以及创建／删除的跨来源预检；未修改学习者正在运行的后端数据。

## 当前版本的边界

- Python 后端的 `tickets` 和浏览器的 `tickets` 是各自内存里的数据，网络传递内容，不共享同一个列表对象。
- 新增、修改和删除只改变后端内存，不会自动写回 `day82/ticket_store.py`；重启后端会恢复初始工单。
- `Field(min_length=1)` 拒绝空字符串，返回 422；当前不会自动去掉空格，只含空格的标题仍能通过。
- 创建、删除失败目前在浏览器 Console 记录错误并恢复按钮，没有实现给客户看的弹窗或错误提示区。
- 编号沿用最后一条加一，删掉末尾记录或删空列表后可能复用旧编号；这是学习版本，后续持久化时再调整编号方案。
