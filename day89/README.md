# Day 89：让网页显示 Python 后端的工单

## 今天解决什么问题

客户打开工单网页，希望看到后台当前保存的问题记录。本节把以前连接练习用 json-server 的网页，改为读取自己写的 Python 后端。
复用 Day 71 的六个网页文件，仅将 `constants.js` 中的接口地址改为 `http://127.0.0.1:8001/tickets`。
现有按钮及其代码也随文件复制过来；本节确认读取流程，创建、删除的完整联调放在 Day 90。

| 课程 | 解决的问题 | 合起来的实际用途 |
| --- | --- | --- |
| Day 88 | 允许来自 5500 的网页跨来源读取 8001 的回复 | 网页能够和自己的 Python 后端交换数据 |
| Day 89 | 获取工单并显示列表 | 客户打开网页就能看到问题记录 |
| Day 90 | 网页创建、删除与后端联调 | 客户提交或删除记录，并看到处理结果 |
| Day 91 | 网页编辑、状态修改与后端联调 | 工作人员持续处理工单 |

之后接入数据库，让数据能够长期保存；再学习部署，让客户能从自己的设备访问系统。

## 三个角色与两个终端

| 角色 | 实际工作 | 当前位置 |
| --- | --- | --- |
| 浏览器 | 取得网页，运行 JavaScript，发送请求，展示工单 | 自己电脑上的 Chrome，扮演客户使用的工具 |
| 5500 的文件服务 | 将 HTML、JavaScript 等文件交给浏览器 | 第二个终端启动的 `http.server` |
| 8001 的业务服务 | 查询、创建、修改、删除工单 | 第一个终端启动的 Uvicorn 和 Day 88 Python 应用 |

5500、8001 是两个服务接收请求的入口编号。浏览器分别访问它们，5500 不转发这次工单查询。
两个服务目前都运行在自己的电脑上；`127.0.0.1` 表示访问者自己的设备。正式客户通常只操作网页，不需要打开终端。

## 启动与访问

在仓库根目录 `fde-90-days-` 的第一个 PowerShell 终端启动后端：

```powershell
.\.venv\Scripts\python.exe -m day88.run
```

沿用 Day 86 配置，当前端口是 8001，以启动日志为准。第二个终端启动网页文件服务：

```powershell
.\.venv\Scripts\python.exe -m http.server 5500 --bind 127.0.0.1
```

两个服务已经运行时可以继续使用，不要重复启动。打开 `http://127.0.0.1:5500/day89/index.html`。
页面路径变成 `/day89/index.html`，来源仍是 `http://127.0.0.1:5500`，继续使用 Day 88 的 CORS 配置。

## 一次获取工单的完整流程

```text
浏览器向 5500 获取 index.html 和 JavaScript 文件
  → 浏览器执行 main.js 最后的 loadTicketsFromApi()
  → renderLoading() 显示正在加载，暂时禁用重新加载按钮
  → fetch(TICKETS_API_URL) 向 8001 发送 GET /tickets
  → Uvicorn 接收请求，交给 Day 88 的 FastAPI 应用
  → get_tickets() 调用 Day 82 的 list_tickets(status, limit)
  → 读取后端内存中的 tickets 列表，筛选并限制数量
  → FastAPI 按响应模型处理结果，生成 JSON 回复
  → 浏览器的 response.json() 将回复解析成 JavaScript 数组
  → setTickets(loadedTickets) 更新浏览器当前使用的数据
  → render(loadedTickets, editingId) 更新数量、文字和按钮
  → finally 恢复重新加载按钮
```

这次没有传筛选参数，默认不筛选状态、最多返回十条；初始数据共四条，因此显示四条。
CORS 提供浏览器跨来源读取许可，不负责保存数据。点击“重新加载工单”会再执行一次相同查询。

## 工单保存在哪里

| 位置 | 内容和作用 |
| --- | --- |
| 硬盘上的 `day82/ticket_store.py` | 四条初始数据：API 登录失败、API 修改发票、支付失败、导出报表失败 |
| Python 后端的内存 | 启动时创建的列表，供实际查询、新增、修改、删除使用 |
| 浏览器的内存 | 将网络回复解析后得到的另一份数组，供网页显示 |

两边都叫 `tickets`，但不是跨网络共享的同一个列表对象。只修改浏览器数组不会自动改变后端数据。
`data.js` 中原有的两条本地示例，在读取成功后由后端返回的数据替换。
刷新网页会重新查询后端；重启后端则重新加载初始数据，内存中的新增和修改不会自动写回 Python 文件。

## 显示状态与核对方法

| 情况 | 当前代码的行为 |
| --- | --- |
| 查询成功 | 显示工单数量及列表，状态值转换为待处理、处理中、已完成 |
| 返回空数组 | 显示“当前有0个工单”，列表为空，不属于加载错误 |
| 请求失败或回复状态表示失败 | 显示“工单加载失败,请稍后重试”，控制台记录错误，重新加载按钮恢复 |
| 服务恢复后重新加载 | 再次查询并展示取得的数据 |
| 请求仍在等待 | 保留“正在加载工单”，当前代码没有设置主动放弃等待的超时 |

学习者已在真实页面确认四条后端工单正常显示，并完成获取流程的讲解。
助手另用实际 Chrome 检查正常列表、空列表、请求失败及恢复：正常读取四条；仅在测试浏览器拦截查询回复为空数组时显示零条；模拟连接失败时显示失败并恢复按钮；撤销拦截后重新取得真实四条。测试没有删除后端工单，也没有停止学习者服务。
本次曾出现一直加载：后端进程存在但请求未及时回应，重启后恢复；尚未确定该运行问题的根因，不据此认定前端代码错误。
`/favicon.ico` 的 404 表示缺少网页小图标，不影响工单列表。

可一次核对打开页面、重新加载、后端停止后失败、恢复后重新加载这几种情况；空列表可用受控模拟检查，避免为了测试删除真实数据。
